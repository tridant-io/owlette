# A site has a plan, and its owner pays

owlette's first plan gates (on dev since october 2026, dormant) read one plan per account: the site owner's, applied to every site they own. tridant id, which sells owlette, bills per site instead: each site is one line on its payer's monthly invoice, active machines times that site's tier price, and a site can be free, core or pro on its own. So from 4.2.0 the plan belongs to the site. The server reads it from tridant id per site (`GET /v1/sites/owlette:{siteId}/entitlements`), every gate asks about the site it acts on, and tridant id stays the only source of truth: owlette holds no Stripe key and keeps only a pointer on the site document for the UI. The payer is always the site's owner, and only the owner can change the site's billing, although tridant id would let any organization pay for any site; a payer who is not the owner is a case nobody has asked for, and it would need its own consent and transfer rules. What tridant id cannot count is owlette free, which is per account: an account has one free site, and its sites on owlette free hold at most one machine between them, which owlette counts itself from the sites the account owns. Every further site is created on core or pro, chosen per site, and an account can own any number of each. Core and pro differ by features and by pro's three-machine minimum, never by how many sites they allow. The site limit counts unpaid sites: not billed, and no trial covers it. A further site goes from creation straight into its upgrade; one whose checkout is left unpaid stays on owlette free, the machine count keeps it empty while the free site holds its machine, and while it exists no other site is created. A billed site whose card has failed past tridant id's grace reads owlette free and shares the free machine, but its billing still runs, so it is never an unpaid site: its owner has nothing to upgrade. tridant id's own `owlette.sites` is not read: it answers for one site and never sees the account's others. The 14-day trial is tridant id's, one per organization, and covers every site the owner has registered there.

Amended 2026-11-20, when owlette took up tridant id's contract of 2026-11-16. The decision stands; three things it rested on changed. First, a report after the 1st does count. tridant id bills the newest report it holds for a period, and holds a closed period's invoice open for 24 hours after the period ends, so a report dated inside that period still lands on it. Treating the 23:30 run on a month's last day as final lost the machines first seen that day whenever the run failed or tridant id did not file its report, and every machine last seen between 23:30 and midnight, for want of one more call a day: owlette now saves each billed site's report and resends the month, recounted to its last millisecond, at 06:00 UTC the morning after. Second, the trial is once per owlette account as well as once per organization. tridant id refuses a second trial (`trial_already_used`) to an account that had one on an organization since closed, so a closed organization buys no fresh trial; owlette records the refusal, never retries it, and tells the owner. Third, the pointer on the site document is no longer the only copy of a site's plan and founders rate, which tridant id's site answer did not carry and now does. Where tridant id's answer bills the site, owlette shows that answer, so the dashboard shows what tridant id bills; the pointer is the fallback, with plans off or tridant id unreachable, and on the account's plan page once the billing ended, and still the only record of who pays, which tridant id's answer does not say.

## Consequences

- Anything that asks "is this allowed on this plan" takes a site id, never a user id. `resolveSitePlan` and `requireEntitlement` are the two ways in; a per-user plan check is a bug.
- A plan refusal is 402. It is never 401 or 403 on an agent route: fielded agents delete their tokens when a refresh is refused.
- When tridant id cannot be reached, or answers something unreadable, the site is unrestricted. A site tridant id does not know is free. An expired or wrong api key therefore turns every gate off quietly, which is why the client logs `rejected` and `Sunset` at error.
- A site in a trial, or billed in good standing, never counts toward the free limits, and during the trial any number of sites can be created, so a trial that ends can leave an account with several sites on owlette free. Nothing is unpaired or deleted: new pairings to them and new sites are refused, and the machines beyond the first show the upgrade notice.
- Transferring a site stops its billing at the period end, and the new owner upgrades again. Deleting a site stops its billing first. Deleting an account unlinks it from its tridant organization.
- Usage is reported every day at 23:30 UTC, and each billed site's report is saved with tridant id's answer. tridant id bills the newest report it holds for a period and holds the closed period's invoice open for 24 hours, so at 06:00 UTC the morning after a period ends owlette recounts it to its last millisecond and sends it again. `docs/runbooks/plans-and-billing.md` lists the cases that pass cannot settle.
- `SITE_BILLING_MANAGE` is the owner's alone and is checked even while `capability_enforcement` is off: the switch fails toward availability, and letting a member put sites on the owner's card is not availability.
- An account whose email already has a tridant organization is never joined to it by email. The owner signs in to tridant id and the fresh ID token is the consent (`POST /v1/billing/link`).
- Everything stays behind `PLAN_ENFORCEMENT`. Rollback is turning it off; nothing a customer paid for is lost, because tridant id holds it.
