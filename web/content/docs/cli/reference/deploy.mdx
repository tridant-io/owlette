---
title: "deploy"
description: "deploy runs classic installer deployments: it sends a silent-install command for one installer file to a list of machines and tracks each machine's install. it is not owlette roost deploy, which ships roost versions."
keywords: ["install software", "software rollout"]
---

> **disambiguation**: `owlette deploy …` downloads one installer onto each target machine and runs it with silent-install flags. [`owlette roost deploy`](/docs/cli/reference/roost#deploy) ships a content-addressed roost version to a fleet. same word, different surfaces.

verbs:

- [`deploy create`](#create) — start a deployment to one or more machines
- [`deploy list`](#list) — list deployments on a site, one page per run
- [`deploy get`](#get) — print one deployment with each target's status
- [`deploy retry`](#retry) — re-queue the targets that failed
- [`deploy cancel`](#cancel) — cancel targets that have not started
- [`deploy uninstall`](#uninstall) — queue an uninstall on every target
- [`deploy delete`](#delete) — delete a finished deployment's record

every verb takes `--site <siteId>`. every mutation sends an `Idempotency-Key` (default `cli-deploy-<verb>-<uuid>`); pass `--idempotency-key <key>` to pin one. if a mutation fails before a response arrives, the CLI prints the key and the `--idempotency-key` to re-run with.

## create

creates a deployment and queues an install command on each machine in `--machines`.

```bash
owlette deploy create --site <siteId> --name <name> --installer-url <url> --installer-name <name> --silent-flags <flags> --machines <csv> [--verify-path <path>] [--sha256 <hex>] [--close-processes <csv>] [--suppress-projects <csv>] [--parallel] [--idempotency-key <key>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the deployment |
| `--name <name>` | string | yes | deployment name |
| `--installer-url <url>` | HTTPS URL | yes | where agents download the installer |
| `--installer-name <name>` | string | yes | file name to save the installer as (for example `Owlette-Installer-v2.10.0.exe`) |
| `--silent-flags <flags>` | string | yes | flags passed to the installer (for example `/S`) |
| `--machines <csv>` | string | yes | target machine IDs, comma-separated, at least one |
| `--verify-path <path>` | string | no | path that must exist after install for it to count as a success |
| `--sha256 <hex>` | string | no | 64-character SHA-256 of the installer; agents refuse a file that does not match |
| `--close-processes <csv>` | string | no | process exe names agents close before installing |
| `--suppress-projects <csv>` | string | no | project names or paths agents suppress before installing |
| `--parallel` | boolean | no | install on all targets at once (default: one at a time) |
| `--idempotency-key <key>` | string | no | `Idempotency-Key` header |

an empty `--machines`, or a `--close-processes` / `--suppress-projects` that is present but empty, fails before a request is sent. a site may target at most `sites/{siteId}.deployQuota` machines per deployment (default 100); more returns `413 over_quota`, and the CLI prints the `max_targets` and `requested` counts.

human mode prints `owlette: deployment <id> created on <siteId> — status <status>, <n> target(s)`. `--json` prints the raw response: `deploymentId`, `siteId`, `status` and `targets`.

### examples

```bash
owlette deploy create --site site-1 \
  --name "td-2024.39000 rollout" \
  --installer-url https://cdn.example.com/td-2024.39000.exe \
  --installer-name td-2024.39000.exe \
  --silent-flags "/S" \
  --machines m_abc,m_def,m_ghi \
  --verify-path "C:\Program Files\Derivative\TouchDesigner\bin\TouchDesigner.exe" \
  --sha256 9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08 \
  --parallel
```

backing: `POST /api/sites/{siteId}/deployments`.

## list

lists deployments on a site, newest first, one page per run.

```bash
owlette deploy list --site <siteId> [--limit <n>] [--cursor <token>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site to list |
| `--limit <n>` | integer | no | page size; the server accepts 1–100 (default 25) |
| `--cursor <token>` | string | no | `next_page_token` from an earlier page |

the table has `id`, `name`, `status`, `targets`, `installer` and `createdAt`, or prints `(no deployments)`. when more pages remain it ends with `next page: --cursor <token>`. `--json` prints the raw response: `{ "items": [...], "next_page_token": "..." }`.

### examples

```bash
owlette deploy list --site site-1
```

```bash
owlette --json deploy list --site site-1 --limit 50 | jq -r '.items[] | select(.status == "failed") | .id'
```

backing: `GET /api/sites/{siteId}/deployments?page_size=&page_token=`.

## get

prints one deployment, then a table of its targets with `machineId`, `status` and `error`.

```bash
owlette deploy get <deploymentId> --site <siteId> [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the deployment |

`--json` prints the raw record: `id`, `siteId`, `name`, `installer_name`, `installer_url`, `silent_flags`, `verify_path`, `sha256_checksum`, `parallel_install`, `targets`, `status`, `createdAt`, `completedAt` and `updatedAt`.

### examples

```bash
owlette deploy get dep_abc123 --site site-1
```

```bash
owlette --json deploy get dep_abc123 --site site-1 | jq '.targets[] | select(.status == "failed")'
```

backing: `GET /api/sites/{siteId}/deployments/{deploymentId}`.

## retry

re-queues every target whose status is `failed`. other targets are left alone.

```bash
owlette deploy retry <deploymentId> --site <siteId> [--idempotency-key <key>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the deployment |
| `--idempotency-key <key>` | string | no | `Idempotency-Key` header |

`--json` prints `deploymentId`, `siteId`, `status`, `retried` and `machine_ids`.

### examples

```bash
owlette deploy retry dep_abc123 --site site-1
```

backing: `POST /api/sites/{siteId}/deployments/{deploymentId}/retry`.

## cancel

cancels the targets that have not started. installers already running are not interrupted.

```bash
owlette deploy cancel <deploymentId> --site <siteId> [--yes] [--idempotency-key <key>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the deployment |
| `--yes` | boolean | no | skip the `[y/N]` prompt; required when stdin is not a tty |
| `--idempotency-key <key>` | string | no | `Idempotency-Key` header |

`--json` prints `deploymentId`, `siteId`, `status`, `cancelled` and `machine_ids`.

### examples

```bash
owlette deploy cancel dep_abc123 --site site-1
```

```bash
owlette --json deploy cancel dep_abc123 --site site-1 --yes
```

backing: `POST /api/sites/{siteId}/deployments/{deploymentId}/cancel`.

## uninstall

queues an uninstall of the deployment's software on every target machine. the calling key needs `site=<id>` with both `write` **and** `admin`; without `admin` the server returns `403 scope_insufficient` and the CLI adds a hint naming the missing scope.

```bash
owlette deploy uninstall <deploymentId> --site <siteId> [--yes] [--idempotency-key <key>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the deployment |
| `--yes` | boolean | no | skip the `[y/N]` prompt; required when stdin is not a tty |
| `--idempotency-key <key>` | string | no | `Idempotency-Key` header |

`--json` prints `deploymentId`, `siteId`, `status`, `queued` and `machine_ids`.

### examples

```bash
owlette deploy uninstall dep_abc123 --site site-1
```

```bash
owlette deploy uninstall dep_abc123 --site site-1 --yes
```

backing: `POST /api/sites/{siteId}/deployments/{deploymentId}/uninstall`.

## delete

deletes a finished deployment's record. it does **not** uninstall anything — run [`uninstall`](#uninstall) first if the software should go. a deployment that is still running returns `409 deployment_in_flight`.

```bash
owlette deploy delete <deploymentId> --site <siteId> [--yes] [--idempotency-key <key>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the deployment |
| `--yes` | boolean | no | skip the `[y/N]` prompt; required when stdin is not a tty |
| `--idempotency-key <key>` | string | no | `Idempotency-Key` header |

`--json` prints `deploymentId`, `siteId` and `deleted`.

### examples

```bash
owlette deploy delete dep_abc123 --site site-1 --yes
```

backing: `DELETE /api/sites/{siteId}/deployments/{deploymentId}`.

## exit codes

- `0` — success, including a declined prompt (`cancel aborted`, `uninstall aborted`, `delete aborted`)
- `1` — network failure, a non-2xx response (`413 over_quota`, `403 scope_insufficient`, `409 deployment_in_flight`, `idempotency_key_mismatch`), or a missing required flag
- `2` — an empty `--machines`, an empty `--close-processes` or `--suppress-projects`, a `--limit` that is not a positive integer, `cancel`/`uninstall`/`delete` without `--yes` when stdin is not a tty, or no token configured

## notes

- **scope**: site-scoped. `list` and `get` need `site=<id>:read`; `create`, `retry`, `cancel` and `delete` need `site=<id>:write`; `uninstall` needs `write` and `admin`
- **JSON**: raw objects with no `{ ok, data }` wrapper
- **idempotency**: a retry with the same key replays the cached response instead of queueing the installs twice — see [idempotency](/docs/api/idempotency)
- **related**: [`roost deploy`](/docs/cli/reference/roost#deploy) for roost versions, [`installer`](/docs/cli/reference/installer) for owlette's own agent installers, [`machine`](/docs/cli/reference/machine) for the target machine IDs
