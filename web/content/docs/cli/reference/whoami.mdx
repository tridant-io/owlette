---
title: "whoami"
description: "whoami asks the server who the active profile's token belongs to — user ID, email, the key's scopes and environment — and prints the local context the CLI used to make the request. no site or machine targeting."
---

[`auth status`](/docs/cli/reference/auth#status) is an alias of `whoami`: both run the same code and print the same output, so use whichever name reads better in a script.

---

## whoami

```bash
owlette whoami [--json]
```

no verb-specific flags. the global `--profile` and `--api-url` pick the profile and host.

### examples

```bash
# one key/value pair per line
owlette whoami
# user id     u_abc...
# email       you@example.com
# scopes      site:*=read|write|deploy
# environment live
# apiUrl      https://owlette.app
# profile     default
# configPath  /home/you/.config/owlette/config.toml
# credential  token-file /home/you/.config/owlette/credentials.json
```

```bash
owlette whoami --json | jq -r '.whoami.userId'
```

```bash
# check another profile without exporting OWLETTE_PROFILE
owlette --profile dev whoami
```

backing: `GET /api/whoami` with `Authorization: Bearer <token>`.

## output

### human mode

eight aligned key/value lines on stdout:

| field | source | meaning |
|---|---|---|
| `user id` | API | the user ID the token resolves to |
| `email` | API | the account email, or `(unknown)` |
| `scopes` | API | `<resource>:<id>=<perms>` per scope, comma-separated, permissions joined by a pipe; `(legacy key — full access, no scope list)` for pre-scope keys; `(session auth — no api key)` when no API key was used; `(none)` for an empty list |
| `environment` | local first, then API | `live`, `test`, or `(unset)` |
| `apiUrl` | local | the resolved API host |
| `profile` | local | the active profile name |
| `configPath` | local | the `config.toml` the CLI read, or `(no config file)` |
| `credential` | local | where the token came from: `env`, `keychain`, `token-file <path>`, `config.toml (legacy)`, or `(none)` |

### JSON mode (`--json`)

```json
{
  "apiUrl": "https://owlette.app",
  "profile": "default",
  "configPath": "/home/you/.config/owlette/config.toml",
  "credentialPath": "/home/you/.config/owlette/credentials.json",
  "credentialSource": "token-file",
  "environment": "live",
  "whoami": { "userId": "u_abc...", "email": "you@example.com", "role": "admin", "key": { }, "rateLimit": { }, "quota": { }, "primarySiteId": "site-1" }
}
```

`whoami` is the raw `GET /api/whoami` body: `userId`, `email`, `role`, `key` (`keyId`, `name`, `keyPrefix`, `scopes`, `environment`, `expiresAt`, `lastUsedAt`, `isLegacy`, or `null` for session auth), `rateLimit`, `quota` and `primarySiteId`. `credentialPath` is the `credentials.json` path when the profile's stored credential was read from that file, otherwise `null`. there is no `{ ok, data }` wrapper — see [JSON output shapes](/docs/cli/overview#json-output-shapes).

---

## exit codes

- `0` — success
- `1` — network failure or a non-2xx response from `GET /api/whoami` (for example `401 token_expired`)
- `2` — no token configured: set `OWLETTE_TOKEN` or run `owlette auth login`

---

## notes

- **scope**: the CLI's own credential; no site or machine
- **alias**: [`auth status`](/docs/cli/reference/auth#status) — same code path, same output
- **token source**: `OWLETTE_TOKEN`, then the keychain or `credentials.json` entry for the active profile, then a legacy `token` in `config.toml`
- **related**: [`auth login`](/docs/cli/reference/auth#login) to store a token, [`key list`](/docs/cli/reference/key#list) for the server-side view of your keys
