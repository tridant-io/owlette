---
title: "trigger"
description: "trigger sends one synthetic webhook event to a URL, for testing a receiver and its signature check. it posts from the CLI itself, or with --via-api asks the server to sign and send the event."
keywords: ["test webhook", "fake event", "mock event"]
---

two modes:

- **direct** (the default): the CLI builds the body, signs it when you give it a secret, and posts it to `--to` itself — no token needed
- **server probe** (`--via-api`): the CLI calls `POST /api/webhooks/probe?siteId=<siteId>` and the server signs and sends one delivery to `--to`

neither mode creates a subscription or puts anything on the [`listen`](/docs/cli/reference/listen) stream.

---

## trigger

```bash
owlette trigger <event> --to <url> [--site <siteId>] [--via-api] [--signing-secret <secret>] [--payload <json> | --payload-file <path>] [--id <delivery-id>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `<event>` | string | yes | event kind, for example `version.published` |
| `--to <url>` | URL | yes | where the event is sent |
| `--site <siteId>` | string | with `--via-api` | site for the probe's query string; also fills `siteId` in a canned payload |
| `--via-api` | boolean | no | send through the server probe instead of from the CLI |
| `--signing-secret <secret>` | string | no | direct mode: sign the body as `Roost-Signature: t=<unix>,v1=<hmac_sha256_hex>`. probe mode: passed to the server, which needs at least 32 characters and mints a secret when you send none |
| `--payload <json>` | JSON string | no | payload to send instead of the canned one; wins over `--payload-file` |
| `--payload-file <path>` | path | no | read the payload from a JSON file |
| `--id <delivery-id>` | string | no | direct mode `Roost-Delivery` value (default: a random UUID). probe mode only logs it — the server assigns its own delivery ID |

canned payloads exist for every event in the [event catalog](/docs/api/webhooks#event-catalog):

- `version.published`, `version.rolled_back`
- `deployment.started`, `deployment.completed`, `deployment.failed`
- `machine.online`, `machine.offline`
- `chunk.garbage_collected`, `chunk.verify_failed`
- `quota.warning`, `quota.exceeded`
- `api_key.used`, `api_key.expired`

in direct mode another event name works only with `--payload` or `--payload-file`. the server probe accepts catalog events only, payload or not.

## direct mode

the default whenever `--via-api` is absent. the CLI sends:

```http
POST <url>
Content-Type: application/json
Roost-Event: <event>
Roost-Delivery: <delivery-id>
Roost-Signature: t=<unix>,v1=<hmac_sha256_hex>
```

`Roost-Signature` is present only with `--signing-secret`; the HMAC-SHA256 covers `<t>.<body>`.

### examples

```bash
# a canned version.published body, signed, to a local receiver
owlette trigger version.published \
  --site site-1 \
  --to http://localhost:3000/hooks \
  --signing-secret whsec_local
```

```bash
# a fixed delivery id, for testing receiver de-duplication
owlette trigger deployment.failed \
  --to http://localhost:3000/hooks \
  --id test-delivery-001 \
  --signing-secret whsec_local
```

```bash
# a custom event with an inline body
owlette trigger custom.test \
  --to http://localhost:3000/hooks \
  --payload '{"siteId":"site-1","ok":true}'
```

human mode logs the request and the response status (with up to 120 characters of the response body) to stderr. `--json` prints to stdout:

```json
{
  "mode": "direct",
  "to": "http://localhost:3000/hooks",
  "status": 200,
  "headers": {
    "Content-Type": "application/json",
    "Roost-Event": "version.published",
    "Roost-Delivery": "test-delivery-001",
    "Roost-Signature": "t=1714000000,v1=..."
  },
  "body": { "roostId": "rst_synthetic_01", "siteId": "site-1" },
  "responseText": "ok"
}
```

## server-probe mode

selected with `--via-api`. it needs a token, `--site` and `--to`. the server checks the URL like a real subscription — `https` only, ports 80, 443, 8080 or 8443, no private, loopback or link-local addresses — so `localhost` is refused; use direct mode for a local receiver.

```bash
owlette trigger version.published \
  --site site-1 \
  --to https://example.com/hooks/owlette \
  --via-api
```

```bash
owlette --profile dev trigger machine.offline \
  --site site-1 \
  --to https://example.com/hooks/owlette \
  --via-api \
  --payload-file ./fixtures/machine-offline.json
```

backing: `POST /api/webhooks/probe?siteId=<siteId>` with body `{ url, event, payload, signingSecret? }`. the CLI always sends a payload, canned or yours.

human mode prints the response status and body to stderr, plus `owlette: webhook probe delivery failed: …` when the receiver did not answer 2xx. a `404` from the probe route prints a hint to drop `--via-api`. `--json` prints:

```json
{
  "mode": "server-probe",
  "status": 200,
  "request": {
    "url": "https://example.com/hooks/owlette",
    "event": "version.published",
    "payload": { "roostId": "rst_synthetic_01", "siteId": "site-1" }
  },
  "response": {
    "status": 200,
    "durationMs": 182,
    "deliveryId": "5b0c…",
    "event": "version.published",
    "requestBody": "{\"roostId\":\"rst_synthetic_01\",…}",
    "signature": "t=1714000000,v1=...",
    "signingSecret": "whsec_…",
    "responseBody": "ok"
  }
}
```

`response.status` is the receiver's status, or `null` with a `networkError` when it could not be reached. `response.signingSecret` echoes your secret or the one the server minted.

## payloads

without `--payload` or `--payload-file` the CLI starts from the canned payload for the event, then:

- replaces `siteId: null` with `--site` when given
- fills `lastHeartbeat` (`machine.online`, `machine.offline`), `blockedAt` (`quota.exceeded`) and `expiresAt` (`api_key.expired`) with the current time

a `--payload` or `--payload-file` that is not valid JSON, or a file that cannot be read, exits `2`.

---

## exit codes

- `0` — the request went through and, in probe mode, the receiver answered 2xx
- `1` — network failure; a non-2xx from the receiver (direct) or from the probe API; in probe mode, a receiver that answered non-2xx or could not be reached; or a `404` probe route
- `2` — a missing `--to`; with `--via-api`, no token or no `--site`; an event with no canned payload and no payload override; invalid payload JSON or an unreadable payload file

---

## notes

- **scope**: direct mode makes no owlette API call. probe mode needs `site=<id>:write`, so probe firings land in the audit log
- **headers**: direct mode always sends `Roost-Event` and `Roost-Delivery`
- **related**: [webhooks](/docs/api/webhooks) for the signature format and verification code, [`listen`](/docs/cli/reference/listen) to forward the event stream, [webhook](/docs/cli/reference/webhook) for subscription routes
