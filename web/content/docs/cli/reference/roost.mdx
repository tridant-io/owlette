---
title: "roost"
description: "a roost is a content-addressed bundle of files — a TouchDesigner project, a media payload, a build — that you push once and agents pull onto target machines. every verb on this page takes --site."
keywords: ["upload project", "sync files", "file distribution"]
---

verbs:

- [`roost push`](#push) — chunk, de-duplicate, upload and publish a directory as a new version
- [`roost list`](#list) — list roosts on a site
- [`roost get`](#get) — print one roost's record
- [`roost diff`](#diff) — compare two versions of a roost
- [`roost versions`](#versions) — list a roost's published versions
- [`roost deploy`](#deploy) — roll a version out, canary first and then the fleet

to go back a version, use the top-level [`owlette rollback`](/docs/cli/reference/rollback).

> **disambiguation**: `owlette roost deploy` ships a roost version. [`owlette deploy`](/docs/cli/reference/deploy) runs classic installer deployments. same word, different surfaces.

<Callout type="warn" title={"write --version=<ref>, with an equals sign"}>

`roost diff` and `roost deploy` take a `--version` flag, but `--version` is also the global flag that prints the CLI version, and it is matched anywhere on the command line. `owlette roost deploy rst_x --site site-1 --version vrs_abc` prints `1.0.0-rc.0`, deploys nothing, and exits `0`. write `--version=vrs_abc` so the value reaches the command.

</Callout>

## push

walks `<dir>`, splits every non-empty file into 4 MiB chunks addressed by SHA-256, asks the server which chunks it lacks, uploads only those through signed URLs, then publishes a new version on `<roostId>`.

```bash
owlette roost push <dir> --to <roostId> --site <siteId> [--name <name>] [-m <text>] [--targets <csv>] [--extract-path <path>] [--idempotency-key <key>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--to <roostId>` | string | yes | roost to publish to |
| `--site <siteId>` | string | yes | site that owns the roost |
| `--name <name>` | string | no | set the roost's display name |
| `-m, --description <text>` | string | no | summary of this version, at most 500 characters |
| `--targets <csv>` | string | no | machine IDs, comma-separated; replaces the roost's targets |
| `--extract-path <path>` | string | no | set the roost's extract root on the machines |
| `--idempotency-key <key>` | string | no | `Idempotency-Key` for the publish request (default `cli-push-<uuid>`) |

the walk skips `.git` and `node_modules` directories and zero-byte files, follows symlinks only when they stay inside `<dir>`, and does not read `.gitignore`. progress goes to stderr. pushing content identical to the current version publishes nothing new.

the publish is a compare-and-swap on the roost's current version. if another push lands first the server answers `412`; the CLI re-reads the current version and retries, up to 5 attempts in all, adding `-1`, `-2`, … to the idempotency key.

human mode ends with `owlette: published <versionId> (#<n>)` and the previous version ID. `--json` prints `{ "versionId", "versionNumber", "currentVersionId", "previousVersionId" }` on stdout and suppresses the progress lines.

### examples

```bash
owlette roost push ./my-project --to rst_my_project --site site-1
```

```bash
# a summary, and a new target list
owlette roost push ./dist --to rst_my_project --site site-1 \
  -m "fix: signage scaling on 4k panels" \
  --targets m_lobby_01,m_lobby_02
```

```bash
# ci: capture the new version id
owlette --json roost push ./build --to rst_ci_build --site site-1 | jq -r '.versionId'
```

backing: `POST /api/chunks/check` and `POST /api/chunks/upload-urls` in batches of 900 hashes, a signed `PUT` per missing chunk (8 at a time), `GET /api/roosts/{roostId}?siteId=` for the current version, then `POST /api/roosts/{roostId}/versions` with `expectedCurrentVersionId`.

## list

lists the roosts on a site. the CLI follows the server's pages until there are none left or `--limit` is reached.

```bash
owlette roost list --site <siteId> [--page-size <n>] [--limit <n>] [--include-deleted] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site to list |
| `--page-size <n>` | integer | no | roosts per request, clamped to 1–100 (default 20) |
| `--limit <n>` | integer | no | stop after this many roosts in total |
| `--include-deleted` | boolean | no | include tombstoned roosts |

the table has `id`, `name`, `current`, `targets` (a count), `status` (`active` or `tombstoned`) and `updated`, or prints `(no roosts)`. `--json` prints `{ "roosts": [...] }`.

### examples

```bash
owlette roost list --site site-1
```

```bash
owlette roost list --site site-1 --include-deleted --limit 50
```

```bash
owlette --json roost list --site site-1 | jq -r '.roosts[].roostId'
```

backing: `GET /api/roosts?siteId=&limit=&cursor=&includeDeleted=`.

## get

prints one roost: ID, name, site, extract path, targets, current and previous version IDs, timestamps, and a summary of the current version (number, ID, description, file count, size, author).

```bash
owlette roost get <roostId> --site <siteId> [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the roost |

`--json` prints the raw record, including `currentVersion` and `previousVersion` summaries and `versionUrl`.

### examples

```bash
owlette roost get rst_my_project --site site-1
```

```bash
owlette --json roost get rst_my_project --site site-1 | jq -r '.currentVersionId'
```

backing: `GET /api/roosts/{roostId}?siteId=`.

## diff

shows which files were added, removed or modified between two versions, with a summary line and the net change in bytes.

```bash
owlette roost diff <roostId> --site <siteId> --against <versionRef> [--version=<versionRef>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the roost |
| `--against <versionRef>` | string | yes | the "from" version |
| `--version=<versionRef>` | string | no | the "to" version (default: the roost's current version); write it with `=` |

a version ref is a version ID (`vrs_…`), a number (`3`, `#3`, `v3`), or `current`, `previous` or `first`. the server resolves it.

human output:

```text
diff vrs_2f1c0a9b… → vrs_9ab04e17… (roost rst_my_project)
  summary: +1 -0 ~2 =140 (+3.12 MiB)

  + media/intro.mp4   3.00 MiB
  ~ project.toe   1.20 MiB → 1.32 MiB (+122.9 KiB)
```

`--json` prints the raw diff: `versionId`, `fromVersion`, `toVersion`, `against`, `roostId`, `siteId`, `summary` (`added`, `removed`, `changed`, `unchanged`, `hasChanges`, `netBytesDelta`), and the `added`, `removed` and `modified` file lists.

### examples

```bash
# what the latest push changed
owlette roost diff rst_my_project --site site-1 --against previous
```

```bash
# two explicit version numbers
owlette roost diff rst_my_project --site site-1 --against '#3' --version='#5'
```

```bash
owlette --json roost diff rst_my_project --site site-1 --against previous | jq '.summary'
```

backing: `GET /api/roosts/{roostId}/versions/{toRef}/diff?siteId=&against=<fromRef>`. without `--version` the CLI first calls `GET /api/roosts/{roostId}` to find the current version.

## versions

lists every version published on a roost, newest first. like `list`, it follows pages until there are none left or `--limit` is reached.

```bash
owlette roost versions <roostId> --site <siteId> [--page-size <n>] [--limit <n>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the roost |
| `--page-size <n>` | integer | no | versions per request, clamped to 1–100 (default 20) |
| `--limit <n>` | integer | no | stop after this many versions in total |

the table has `#`, `versionId`, `description` and `createdAt`, or prints `(no versions)`. `--json` prints `{ "versions": [...] }`, each with `versionId`, `versionNumber`, `description`, `versionUrl`, `createdAt`, `createdBy`, `totalSize`, `totalFiles` and `parentVersionId`.

### examples

```bash
owlette roost versions rst_my_project --site site-1
```

```bash
owlette roost versions rst_my_project --site site-1 --limit 10
```

```bash
owlette --json roost versions rst_my_project --site site-1 | jq -r '.versions[].versionId'
```

backing: `GET /api/roosts/{roostId}/versions?siteId=&limit=&cursor=`.

## deploy

rolls a version out to the roost's targets, or to `--machines`: the server splits the machines into a canary wave and the rest of the fleet and queues the pull commands for the canary wave. `--dry-run` returns the plan and writes nothing.

with `--at` more than 60 seconds in the future, the rollout is stored with stage `scheduled`. a sweep that runs every 5 minutes fires it, queueing exactly the commands an immediate deploy would have; a rollout found more than 30 minutes past its time is marked `aborted` instead of firing late — run the deploy again. see [scheduled rollouts](/docs/api/versions#scheduled-rollouts).

```bash
owlette roost deploy <roostId> --site <siteId> [--version=<versionId>] [--machines <csv>] [--dry-run] [--at <iso8601>] [--idempotency-key <key>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the roost |
| `--version=<versionId>` | string | no | version to deploy (default: the roost's current version); write it with `=` |
| `--machines <csv>` | string | no | machine IDs, comma-separated; replaces the roost's targets for this rollout |
| `--dry-run` | boolean | no | return the plan without writing anything |
| `--at <iso8601>` | string | no | schedule the rollout; anything `Date.parse` accepts, sent as ISO 8601 |
| `--idempotency-key <key>` | string | no | `Idempotency-Key` header (default `cli-deploy-<uuid>`; none on a dry run) |

a real deploy always carries an `Idempotency-Key`, so a retry returns the original rollout instead of starting another. deploying a version whose rollout is still running returns that rollout, and the CLI prints `rollout already in flight`.

human mode prints a label (`dry-run plan`, `rollout started`, `scheduled` or `rollout already in flight`), the version, stage, extract root and version URL, then the canary and fleet machine lists. `--json` prints the raw response: `rolloutId`, `versionId`, `siteId`, `roostId`, `stage`, `canary`, `fleet`, `extractRoot`, `versionUrl`, and `dryRun`, `alreadyRunning` or `scheduled` (`{ at, warning }`) when they apply.

### examples

```bash
# preview the canary and fleet split
owlette roost deploy rst_my_project --site site-1 --dry-run
```

```bash
# deploy the current version to the roost's targets
owlette roost deploy rst_my_project --site site-1
```

```bash
# a pinned version, overnight, for ci
owlette --json roost deploy rst_my_project --site site-1 \
  --version=vrs_abc123 \
  --at 2026-05-01T03:00:00Z | jq -r '.rolloutId'
```

backing: `POST /api/roosts/{roostId}/deploy` with body `{ siteId, versionId?, machines?, scheduleAt?, dryRun? }`.

## exit codes

- `0` — success; also `roost diff` or `roost deploy` with `--version <ref>` written with a space, which prints the CLI version and does nothing (see the warning above)
- `1` — network failure, a non-2xx response, a missing required flag, a chunk upload that failed after its retry, or a publish still conflicting after 5 attempts
- `2` — `push`: `<dir>` is not a directory, it holds no non-empty files, or `--description` is over 500 characters; `diff`: the roost has no current version and no `--version`; `deploy`: an empty `--machines` or an unparseable `--at`; any verb: no token configured

## notes

- **scope**: `list` needs `site=<id>:read`; `get`, `diff` and `versions` need `roost=<id>:read`; `push` needs `site=<id>:write` for the chunk routes and `roost=<id>:write` to publish; `deploy` needs `roost=<id>:deploy`
- **chunks**: 4 MiB, addressed by SHA-256, and de-duplicated across the whole site
- **JSON**: raw objects with no `{ ok, data }` wrapper
- **related**: [`rollback`](/docs/cli/reference/rollback), [roost versions API](/docs/api/versions), [chunks API](/docs/api/chunks), [quota](/docs/cli/reference/quota) for storage use, [`machine deployments`](/docs/cli/reference/machine) for each machine's reported version
