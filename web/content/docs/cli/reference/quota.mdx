---
title: "quota"
description: "quota shows a site's roost storage against its limit and its daily storage, operation and egress usage. both verbs are site-scoped and read-only."
keywords: ["bandwidth", "disk space"]
---

verbs:

- [`quota show`](#show) — current storage snapshot for a site, with recent alarms
- [`quota history`](#history) — one row of usage per UTC day over a window

---

## show

prints the site's committed storage against its limit as a progress bar, the bytes held by in-flight uploads, when the usage was last reconciled, and up to the 20 most recent quota alarms.

```bash
owlette quota show --site <siteId> [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site to read |

the bar line is 20 characters wide and always has this shape:

```text
storage: <committed> / <limit> (NN%) [#####...............]
```

when the response has no limit the CLI prints `storage: <committed> used` instead. `--json` prints the raw snapshot: `siteId`, `usedBytes`, `pendingBytes`, `committedBytes`, `limitBytes`, `fractionUsed`, `lastAlarmLevel`, `lastAlarmAt`, `lastReconciledAt` and `alarms` (each `{ id, threshold, firedAt }`).

### examples

```bash
owlette quota show --site site-1
# site       site-1
#
# storage: 12.4 GiB / 50.0 GiB (25%) [#####...............]
#   pending: 240.0 MiB (in-flight uploads, not yet committed)
#   reconciled at 2026-04-26T03:00:00.000Z
```

```bash
# fraction of the limit in use, 0 to 1
owlette --json quota show --site site-1 | jq '.fractionUsed'
```

```bash
# succeed only if an alarm has ever fired on this site
owlette --json quota show --site site-1 | jq -e '.alarms | length > 0'
```

backing: `GET /api/sites/{siteId}/quota`.

## history

prints one row per UTC day over the window: average stored bytes, class A and class B storage operations, and egress bytes. days with no recorded events show `-` for storage and zeros for the rest.

```bash
owlette quota history --site <siteId> [--period <window>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site to read |
| `--period <window>` | `7d`, `14d`, `30d`, `60d` or `90d` | no | window ending today (default `30d`) |

any other `--period` value fails before a request is sent. the table has `date`, `storage avg`, `class A ops`, `class B ops` and `egress`. `--json` prints the raw rollup: `siteId`, `period`, `days` and `daily` (each `{ date, storageBytesAvg, classAOps, classBOps, egressBytes }`).

### examples

```bash
owlette quota history --site site-1
```

```bash
owlette quota history --site site-1 --period 7d
```

```bash
# total egress over the last 90 days
owlette --json quota history --site site-1 --period 90d \
  | jq '[.daily[].egressBytes] | add'
```

backing: `GET /api/sites/{siteId}/quota/history?period=<window>`.

---

## exit codes

- `0` — success
- `1` — network failure, a non-2xx response (for example `403` without access to the site), or a missing `--site`
- `2` — a `--period` outside the five allowed values, or no token configured

---

## notes

- **scope**: site-scoped, read-only; needs read access to the site
- **committed vs pending**: `committedBytes` is `usedBytes` plus `pendingBytes`. pending bytes belong to uploads that have not been finalised, and they count against the limit — the bar and `fractionUsed` both use `committedBytes`
- **days**: buckets are UTC calendar days and the window includes today, so the last row is a partial day
- **JSON**: raw objects with no `{ ok, data }` wrapper
- **related**: [site](/docs/cli/reference/site) to find site IDs, [roost](/docs/cli/reference/roost) — roost pushes are what fill this storage
