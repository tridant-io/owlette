<Callout type="warn" title={"liveness events only, for now"}>

`GET /api/events/stream` sends `connected` when it opens, `keepalive` every 15 seconds, and `closing` when it shuts the stream after 30 minutes. no roost events flow through it yet. the forwarding below works the same once they do.

</Callout>

## listen

```bash
owlette listen --site <siteId> --forward-to <url> [--events <csv>] [--signing-secret <secret>] [--print]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site whose stream to read |
| `--forward-to <url>` | URL | yes | local endpoint that receives each event as a `POST` |
| `--events <csv>` | string | no | event kinds to forward, comma-separated; must be names from the [event catalog](/docs/api/webhooks#event-catalog). default: everything except `connected` and `keepalive` |
| `--signing-secret <secret>` | string | no | re-sign each forwarded body as `Roost-Signature: t=<unix>,v1=<hmac_sha256_hex>` |
| `--print` | boolean | no | no effect — events are always logged to stderr |

the global `--profile` and `--api-url` pick the profile and host. the command runs until you press `Ctrl-C` or the server closes the stream.

### examples

```bash
# forward everything to a local app
owlette listen --site site-1 --forward-to http://localhost:3000/hooks/owlette
```

```bash
# forward two event kinds only
owlette listen \
  --site site-1 \
  --forward-to http://localhost:3000/hooks/owlette \
  --events version.published,deployment.completed
```

```bash
# re-sign forwarded payloads with a local test secret
owlette listen \
  --site site-1 \
  --forward-to http://localhost:3000/hooks/owlette \
  --signing-secret whsec_local_test
```

backing: `GET /api/events/stream?siteId=<siteId>&api_key=<token>[&events=<csv>]` with `Accept: text/event-stream` and `Authorization: Bearer <token>`.

## stream handling

the CLI reads blocks of this shape, with an optional `id:` line:

```text
event: <kind>
data: <json>

```

`connected` prints `owlette: stream connected` and `keepalive` is counted silently; neither is forwarded. every other event, `closing` included, is forwarded unless `--events` leaves it out — then the CLI prints `owlette: (filtered) <kind>`.

with `--events`, the same list is sent to the server, which rejects any name outside the event catalog with `400` before the stream opens, and is also applied locally. names match exactly after trimming spaces.

---

## forwarded request

each forwarded event becomes:

```http
POST <forward-to>
Content-Type: application/json
Roost-Event: <event kind>
Roost-Delivery: <event id, when the block has one>
Roost-Signature: t=<unix>,v1=<hmac_sha256_hex>
```

the body is the raw `data:` string. with `--signing-secret`, `Roost-Signature` is an HMAC-SHA256 over `<t>.<body>`. without it, the CLI forwards a `roostSignature` value found in the JSON payload, and otherwise sends no signature header.

every response from the local endpoint, 2xx or not, is logged and counted as forwarded. a network-level failure is logged and counted in `forwardErrors`, and the listener carries on with the next event.

---

## output

everything goes to stderr; nothing is written to stdout, and `--json` has no effect. on start:

```text
owlette: listening on https://owlette.app/api/events/stream
       site: site-1
       forwarding to http://localhost:3000/hooks/owlette
       events: all (except keepalive)
       (no re-sign secret — forwarded payloads carry the server's original Roost-Signature if present)
```

while running it logs `owlette: → forwarding <kind>`, `owlette: ← <status> from <url>` and any forward failures. on exit:

```text
owlette: listener stopped. connected=1 events=3 forwarded=3 forwardErrors=0 keepalives=12
```

---

## exit codes

- `0` — you stopped it with `Ctrl-C`
- `1` — the stream could not be opened, the server answered non-2xx (including a `400` for an unknown `--events` name), a read failed, or the server closed the stream — which it does after 30 minutes, after printing `owlette: stream closed by server`. a missing `--site` or `--forward-to` also exits `1`
- `2` — no token configured, or a `--forward-to` that is not a valid URL

## notes

- **scope**: the key needs `site=<id>:read`
- **auth**: the token goes both in the `api_key` query parameter and in the `Authorization` header, so a proxy that strips headers from long-lived requests does not drop it
- **reconnects**: there are none — wrap the command in a loop if you need it to outlive the 30-minute stream
- **related**: [`trigger`](/docs/cli/reference/trigger) to send one synthetic event, [webhooks](/docs/api/webhooks) for the event catalog and signature format, [webhook](/docs/cli/reference/webhook) for the subscription routes
