---
title: "version"
description: "version prints the CLI's package version next to the server's current API date and the dates it supports. no site or machine targeting, and no token needed."
keywords: ["compatibility"]
---

use it to:

- check which API date the server is on before a long script
- see the dates the server accepts in the `Roost-Version` header

`owlette --version` (or `-V`) prints only the CLI version and makes no request.

---

## version

```bash
owlette version [--json]
```

no verb-specific flags.

### examples

```bash
owlette version
# cli 1.0.0-rc.0  |  server 2026-04-22  |  supported versions: 2026-04-22
```

```bash
owlette version --json
# {
#   "cli": "1.0.0-rc.0",
#   "server": "2026-04-22",
#   "supportedVersions": ["2026-04-22"],
#   "minimumVersion": "2026-04-22"
# }
```

backing: `GET /api/version`. the route is unauthenticated; the CLI sends `Authorization: Bearer <token>` when a token is configured, and runs without one.

---

## output

### human mode

one line on stdout:

```text
cli <package version>  |  server <YYYY-MM-DD>  |  supported versions: <date>, <date>, ...
```

### JSON mode (`--json`)

| field | type | meaning |
|---|---|---|
| `cli` | string | the `version` in the nearest `@owlette/cli` `package.json` above the running file, or `"unknown"` |
| `server` | string | `current` from the response — the server's API date |
| `supportedVersions` | string[] | `supported` from the response, in server order |
| `minimumVersion` | string | the earliest date in `supportedVersions` (dates sort lexically) |

there is no `{ ok, data }` wrapper — see [JSON output shapes](/docs/cli/overview#json-output-shapes).

---

## exit codes

- `0` — success
- `1` — network failure, a non-2xx response, or a body without a `current` string and a non-empty `supported` list

---

## notes

- **scope**: none — the endpoint is public
- **dates, not semver**: the server versions its API by `YYYY-MM-DD` date; a client can pin one with the `Roost-Version` request header, and an unsupported date fails with [`unsupported_version`](/docs/api/errors#unsupported_version)
- **related**: [overview](/docs/cli/overview)
