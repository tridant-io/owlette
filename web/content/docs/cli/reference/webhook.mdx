<Callout type="warn" title={"not a cli command"}>

`owlette webhook` is not registered. running `owlette webhook …` prints `error: unknown command 'webhook'` and exits `1`. manage subscriptions in the dashboard under **settings → webhooks**, with the [Node SDK](/docs/api/sdk-node#webhooks), or through the API routes below.

</Callout>

what the CLI does have:

- [`owlette listen`](/docs/cli/reference/listen) — forwards a site's event stream to a local URL
- [`owlette trigger`](/docs/cli/reference/trigger) — sends one synthetic event, directly or through `POST /api/webhooks/probe`

---

## API routes

every route takes `?siteId=<siteId>`. reads need `site=<id>:read`; writes need `site=<id>:write`.

| route | what it does |
|---|---|
| `POST /api/webhooks` | create a subscription from `{ url, events, description? }`. the `whsec_*` signing secret is returned once, here |
| `GET /api/webhooks` | list subscriptions, paginated; soft-deleted ones and secrets are never returned |
| `GET /api/webhooks/{webhookId}` | one subscription: `url`, `events`, `description`, `paused`, last-delivery fields and `failureCount` |
| `PATCH /api/webhooks/{webhookId}` | change `url`, `events`, `description` or `paused` |
| `DELETE /api/webhooks/{webhookId}` | soft-delete; delivery stops on the dispatcher's next tick and a 30-day tombstone is kept |
| `POST /api/webhooks/{webhookId}/rotate-secret` | mint a new secret, returned once; the old one stays valid for receivers for 24 hours |
| `GET /api/webhooks/{webhookId}/deliveries` | deliveries from the last 30 days, newest first, paginated |
| `GET /api/webhooks/{webhookId}/deliveries/{deliveryId}` | one delivery's full request and response |
| `POST /api/webhooks/{webhookId}/deliveries/{deliveryId}/retry` | queue a fresh attempt of one delivery, signed with the current secret |
| `POST /api/webhooks/probe` | sign and send one synthetic event to any URL without a subscription — what `owlette trigger --via-api` calls |

URLs are checked on create, update and probe: `https` only, ports 80, 443, 8080 or 8443, and no private, loopback or link-local addresses. `events` must come from the [event catalog](/docs/api/webhooks#event-catalog).

### examples

```bash
# create a subscription with curl
curl -X POST "https://owlette.app/api/webhooks?siteId=site-1" \
  -H "Authorization: Bearer owk_live_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/hooks/owlette","events":["version.published","deployment.failed"]}'
```

```bash
# test a receiver's signature check without a subscription
owlette trigger version.published --site site-1 --to https://example.com/hooks/owlette --via-api
```

## notes

- **signing**: deliveries carry `Roost-Signature: t=<unix>,v1=<hmac_sha256_hex>` — see [signature verification](/docs/api/webhooks#signature-verification)
- **secrets**: only create and rotate-secret return a secret; it cannot be read back later
- **contract**: request and response shapes are in the [API reference](/docs/api/reference) and the [webhooks guide](/docs/api/webhooks)
- **status**: see the [readiness matrix](/docs/cli/readiness#webhook-noun)
