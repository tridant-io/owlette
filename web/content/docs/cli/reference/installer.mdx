---
title: "installer"
description: "installer manages the platform-wide catalog of owlette agent installers that new machines download. superadmin only: installer=*:read for list and latest, installer=*:write for upload, installer=*:admin for set-latest and delete."
keywords: ["agent release", "publish agent"]
---

each installer version carries one file per platform, keyed the way machines report their platform:

- Windows (`windows_x64`): `Owlette-Installer-vX.Y.Z.exe`
- macOS on Apple silicon (`macos_arm64`): `Owlette-Installer-vX.Y.Z.pkg`
- Linux (`linux_x64`): `Owlette-Installer-vX.Y.Z.deb`

this is owlette's own agent installer, not a site's software deploys — for those see [`deploy`](/docs/cli/reference/deploy).

verbs:

- [`installer list`](#list) — list uploaded versions, newest first
- [`installer latest`](#latest) — show the version marked latest
- [`installer upload`](#upload) — upload one platform's file for a version
- [`installer set-latest`](#set-latest) — mark an uploaded version as latest
- [`installer delete`](#delete) — soft-delete a version

every mutation sends an `Idempotency-Key` (default `cli-installer-<verb>-<uuid>`); if one fails before a response arrives, the CLI prints the key and the `--idempotency-key` to re-run with.

## list

lists installer versions, newest first, one page per run.

```bash
owlette installer list [--include-deleted] [--limit <n>] [--cursor <token>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--include-deleted` | boolean | no | include soft-deleted versions |
| `--limit <n>` | integer | no | page size; the server accepts 1–100 (default 20) |
| `--cursor <token>` | string | no | `next_page_token` from an earlier page |

the table has `version`, `size`, `uploaded`, `status` (`active` or `deleted`) and the first 12 characters of the SHA-256. size and checksum are the version's top-level (Windows) fields; under the table, each version with per-platform files gets an indented `platform  size  sha256` line per file. when more pages remain the output ends with `next page: --cursor <token>`. `--json` prints the raw response: `versions` (each with its `files` map), `next_page_token` and `nextPageToken`.

### examples

```bash
owlette installer list
```

```bash
owlette installer list --include-deleted --limit 50
```

```bash
owlette --json installer list | jq -r '.versions[] | select(.deletedAt == null) | .version'
```

backing: `GET /api/installer?page_size=&page_token=&includeDeleted=`.

## latest

shows the version marked latest: one table row, then a line per platform file.

```bash
owlette installer latest [--json]
```

no verb-specific flags. `--json` prints the raw record, including the `files` map next to the flat Windows fields.

### examples

```bash
owlette installer latest
```

```bash
owlette --json installer latest | jq -r '.files.linux_x64.download_url'
```

backing: `GET /api/installer/latest`.

## upload

uploads one installer file and records it under `--version`. run it once per platform with the same version; each upload adds that platform's entry to the version's `files` map.

<Callout type="warn" title={"write --version=X.Y.Z, with an equals sign"}>

`owlette --version` is the global flag that prints the CLI version, and it is matched anywhere on the command line. `owlette installer upload <file> --version 2.11.0` therefore prints `1.0.0-rc.0`, uploads nothing, and exits `0`. the `--version=2.11.0` form reaches `upload`.

</Callout>

```bash
owlette installer upload <file> --version=<X.Y.Z> [--platform <key>] [--release-notes <text>] [--set-latest] [--idempotency-key <key>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `<file>` | path | yes | the installer file (`.exe`, `.pkg` or `.deb`) |
| `--version=<X.Y.Z>` | semver | yes | version the file belongs to |
| `--platform <key>` | `windows_x64`, `macos_arm64` or `linux_x64` | no | defaults to the platform for the file's extension |
| `--release-notes <text>` | string | no | release notes shown in the dashboard |
| `--set-latest` | boolean | no | mark the version latest after upload — already the default |
| `--idempotency-key <key>` | string | no | `Idempotency-Key` for both server calls (default `cli-installer-upload-<uuid>`) |

a file name without one of the three extensions fails before upload unless `--platform` names a platform, and the server still rejects any file name that does not end in `.exe`, `.pkg` or `.deb`, or whose extension does not match `--platform`.

the CLI runs three steps:

1. `POST /api/installer/upload` reserves the version and platform and returns a signed upload URL
2. `PUT <signed url>` uploads the bytes straight to storage
3. `PUT /api/installer/upload` finalises: the server recomputes the SHA-256 from storage, compares it with the CLI's, writes the metadata, and moves the latest pointer

both server calls carry the same `Idempotency-Key`, so a retry replays them while the signed URL is still valid.

the server marks the version latest unless the request sets `setAsLatest: false`. the CLI sends `setAsLatest` only when you pass `--set-latest`, and has no flag to send `false` — to upload without moving the latest pointer, call the upload API directly.

human mode prints the platform and size before uploading, then the finalised version, SHA-256 and download URL. `--json` prints only the finalise response: `version`, `platform`, `download_url`, `checksum_sha256`, `file_size` and `files`.

### examples

```bash
# one file per platform, all under 2.11.0
owlette installer upload ./Owlette-Installer-v2.11.0.exe --version=2.11.0 --release-notes "fixes display-manager flicker"
owlette installer upload ./Owlette-Installer-v2.11.0.pkg --version=2.11.0
owlette installer upload ./Owlette-Installer-v2.11.0.deb --version=2.11.0
```

backing: `POST /api/installer/upload`, `PUT <signed url>`, then `PUT /api/installer/upload`.

## set-latest

marks an uploaded, active version as latest; new machines then download it.

```bash
owlette installer set-latest <version> [--yes] [--idempotency-key <key>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--yes` | boolean | no | skip the `[y/N]` prompt; required when stdin is not a tty |
| `--idempotency-key <key>` | string | no | `Idempotency-Key` header |

a soft-deleted version returns `version_deleted`. `--json` prints `{ "version": "...", "latest": { } }`.

### examples

```bash
owlette installer set-latest 2.11.0
```

```bash
owlette --json installer set-latest 2.11.0 --yes
```

backing: `POST /api/installer/{version}/set-latest`.

## delete

soft-deletes a version. machines that already installed it keep it; new machines and default listings no longer see it. the server refuses the current latest version (`409 latest_version_protected`) and any delete that would leave fewer than two active versions (`409 min_versions_violated`; the CLI prints the floor). deleting an already-deleted version succeeds and prints `was already deleted (no change)`.

```bash
owlette installer delete <version> [--yes] [--idempotency-key <key>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--yes` | boolean | no | skip the `[y/N]` prompt; required when stdin is not a tty |
| `--idempotency-key <key>` | string | no | `Idempotency-Key` header |

`--json` prints `version`, `deletedAt` and `alreadyDeleted`.

### examples

```bash
owlette installer delete 2.9.0
```

```bash
owlette installer delete 2.9.0 --yes
```

backing: `DELETE /api/installer/{version}`.

## exit codes

- `0` — success, including a declined prompt; also `upload … --version X.Y.Z` with a space, which prints the CLI version and does nothing (see [upload](#upload))
- `1` — network failure, a non-2xx response (`scope_insufficient`, `checksum_mismatch`, `latest_version_protected`, `min_versions_violated`, `version_deleted`, idempotency errors), a failed upload to the signed URL, or a missing `--version`
- `2` — an extension the CLI cannot map and no `--platform`, an unknown `--platform`, an unreadable file, a `--limit` that is not a positive integer, `set-latest`/`delete` without `--yes` when stdin is not a tty, or no token configured

---

## notes

- **scope**: platform-wide, superadmin only — a superadmin session, or an API key with `installer=*:read` (`list`, `latest`), `installer=*:write` (`upload`) or `installer=*:admin` (`set-latest`, `delete`). on `403 scope_insufficient` the CLI adds a hint naming the scope
- **JSON**: raw objects with no `{ ok, data }` wrapper
- **related**: [`deploy`](/docs/cli/reference/deploy) to run other software installers on a site's machines
