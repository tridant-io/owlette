verbs:

- [`audit-log list`](#list) — list records on a site, newest first, following pagination for you
- [`audit-log get`](#get) — print one record with its hash chain and verification report

---

## list

lists audit records on a site, newest first. the CLI keeps requesting pages until there are none left or `--limit` is reached.

```bash
owlette audit-log list --site <siteId> [--kind <csv>] [--actor <actor>] [--since <when>] [--until <when>] [--limit <n>] [--cursor <token>] [--page-size <n>] [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site to read |
| `--kind <csv>` | string | no | event kinds to keep, comma-separated (for example `api_key_used,signed_url_issued`) |
| `--actor <actor>` | string | no | exact actor, for example `apiKey:<keyId>` or `user:<uid>` |
| `--since <when>` | ISO 8601 or duration | no | only records at or after this time; a duration such as `30s`, `15m`, `24h` or `7d` means that long ago |
| `--until <when>` | ISO 8601 or duration | no | drop records recorded after this time |
| `--limit <n>` | integer | no | stop after this many records in total |
| `--cursor <token>` | string | no | resume from a `nextPageToken` printed by an earlier run |
| `--page-size <n>` | integer | no | records per request, clamped to 1–200 (default 50) |

where each filter runs:

- **one `--kind`** goes to the server. **two or more** are filtered by the CLI after each page arrives, so the server still returns every kind.
- **`--until`** is always filtered by the CLI; the server has no `until`. pair it with `--since` so the walk stops early.
- **`--since`** goes to the server; a duration is converted to an ISO 8601 time first. **`--actor`** goes to the server.

human mode prints a table of `recordedAt`, `kind`, `actor` (cut at 32 characters) and `hash`, or `(no records)`. when more records remain it ends with `next cursor: <token>`. `--json` prints `{ "records": [...], "nextPageToken": "<token or empty>" }`, each record with `hash`, `kind`, `actor`, `siteId`, `target`, `occurredAt`, `recordedAt` (epoch ms) and `attributes`. the cursor is a record hash; pass it to `--cursor` to resume.

### examples

```bash
# everything from the last 24 hours
owlette audit-log list --site site-1 --since 24h
```

```bash
# api-key use in the last week, at most 100 records
owlette audit-log list --site site-1 --kind api_key_used --since 7d --limit 100
```

```bash
# calls made by one api key
owlette audit-log list --site site-1 --actor apiKey:key_123 --since 24h
```

```bash
# resume a walk from a saved cursor
owlette --json audit-log list --site site-1 --cursor 9c1f0e7a... | jq '.records | length'
```

backing: `GET /api/sites/{siteId}/audit-log?page_size=&page_token=&kind=&actor=&since=`.

## get

prints one record — kind, actor, occurredAt and attributes — with its chain links (`previousHash`, `hash`) and the server's verification report.

```bash
owlette audit-log get <recordHash> --site <siteId> [--json]
```

| flag | type | required | description |
|---|---|---|---|
| `--site <siteId>` | string | yes | site that owns the record |

`--json` prints the raw response: `siteId`, `hash`, `previousHash`, `recordedAt`, `event` (`kind`, `siteId`, `actor`, `occurredAt`, `attributes`) and `verification` (`ok`, `hashValid`, `linkageValid`, `isGenesis`, `predecessorPresent`, `reason`).

`verification.ok: true` means the record's content hashes to its stored hash and it links to its predecessor, or it is the first record. `false` in any field means the record was altered or its predecessor is missing; `reason` says which. `linkageValid` is `null` (`n/a` in human mode) when there is no predecessor to check.

### examples

```bash
owlette audit-log get 9c1f0e7a... --site site-1
```

```bash
owlette --json audit-log get 9c1f0e7a... --site site-1 | jq '.verification'
```

backing: `GET /api/sites/{siteId}/audit-log/{recordHash}`.

---

## exit codes

- `0` — success
- `1` — network failure, a non-2xx response, or a missing `--site`
- `2` — `--since` or `--until` that is neither ISO 8601 nor a duration, or no token configured

---

## notes

- **scope**: site-scoped, read-only; the key needs `site=<id>:read`
- **verification is server-side**: the CLI does not re-hash records. to verify offline, fetch records with `--json` and recompute the hashes yourself
- **cheapest queries**: a single `--kind` plus `--since` keeps the filtering on the server; client-side filters still download every record in range
- **JSON**: raw objects with no `{ ok, data }` wrapper
- **related**: [overview](/docs/cli/overview) for global flags, [site](/docs/cli/reference/site) to find site IDs
