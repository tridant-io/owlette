**location**: admin panel → members (`/admin/members`)

<Callout type="info" title={"permissions"}>

the page opens for anyone who is an owner or admin on at least one site. it acts on one site at a time. its site selector lists every site you belong to, but on a site where you are only a member the list is refused. every change needs `SITE_MEMBER_MANAGE` on that site, which owners and admins hold.

</Callout>

## the member list

the header shows **total members** and **admins** (the owner is not counted as an admin).

| column | what it shows |
|---|---|
| **member** | the display name if there is one, the email address, and a `you` badge on your own row |
| **role** | `owner`, `admin` or `member`, on this site |
| **actions** | the row menu, or `—` when there is nothing you can do to that row |

the list is the site's active member rows whose accounts still exist and are not deleted. the owner appears through their own row with the `owner` badge. the page never shows which other sites a member belongs to, and never lists anyone who is not on this site.

---

## what the roles mean

| role | on this site |
|---|---|
| **member** | read-only: view machines, capture screenshots, open live view, and watch a [swoop](/docs/dashboard/swoop) session when the site lets members watch. no commands, no configuration |
| **admin** | everything a member can, plus machine commands and configuration, swoop control and swoop settings, deployments, roosts, talons, webhooks, logs, alert rules, schedule presets, enrolling machines, revoking agent tokens, and managing members |
| **owner** | everything an admin can, plus deleting the site and transferring ownership. every site has exactly one |

roles are **per site**. the same person can own one site, administer a second and be a plain member of a third, and their account-level role grants nothing on any of them. the [capability matrix](/docs/dashboard/admin#capability-matrix) lists every capability each role holds.

## adding a member

the person must already have an owlette account: this page adds an existing account to a site and sends no invitation.

1. click **add member**.
2. enter their **email**.
3. choose a **role**: **member** or **admin**.
4. click **add member**.

if no account has that address, the page says **no account found for that email**: ask them to sign up first, then add them.

the role you pick is written for this site only and changes nothing about their account or any other site. the dialog still shows an old hint when you pick **admin**, "admin is an account-level role…"; it no longer applies, and the person joins as an admin.

someone who is already on the site is left as they are. the request succeeds without changing their role, even though the toast says they now have the role you picked; to change it, see [changing a role](#changing-a-role). the site owner cannot be added again (`target_is_owner`), and a deleted account cannot be added.

## removing a member

1. open the row menu.
2. select `remove...`.
3. read the dialog, then click **remove member**.

removal takes away their access to this site at once. any [swoop](/docs/dashboard/swoop) session they are in on the site ends within seconds. their account and any other sites they belong to are untouched.

two rows cannot be removed:

- **the site owner** has no remove action. transfer ownership first (below), then remove them
- **yourself**: the page says **cannot remove yourself**, and the server refuses it too (`cannot_modify_own_membership`). ask another admin on the site

### talon reassignment

talons belong to the site, but a talon with a hoot output or a visual check re-checks its **author's** access on every run. once its author has been removed, it switches itself off on its next run.

when the person you are removing wrote talons on this site, the dialog says how many, names the first five, and offers a successor picker. choosing a successor moves authorship before the membership change; the page then says how many talons moved. if the server refuses the successor, nothing is removed.

the server accepts only a successor who is an owner or admin on this site. the picker filters on account-level role instead, so it can list someone the server will refuse and leave out a site admin who would qualify.

reassignment is never automatic. leave the picker empty and the removal still goes through, leaving the talons with an author who can no longer run them: reassign or delete them afterwards.

## changing a role

a role change applies to **this site only**. the server call is `PATCH /api/sites/{siteId}/members/{uid}` with `{ "role": "admin" }` or `{ "role": "member" }`, from a signed-in session or an API key holding both `write` and `admin` on the site; the CLI equivalent is [`owlette site set-role`](/docs/cli/reference/site#set-role).

the server enforces:

- the **owner's** role cannot change (`409 cannot_change_owner_role`). ownership moves only by transfer, so a site is never left without one
- only `admin` and `member` can be assigned
- you cannot change your **own** role (`403 cannot_modify_own_membership`)
- the person must already be on the site (`404`)

demoting someone to member ends any swoop session in which they hold control. a session they are still allowed to watch carries on.

the dashboard does not offer this to site owners and admins yet: the row menu's `change role...` is shown only to owlette's own operators. use the API or the CLI. the dialog behind that menu item also says "this changes the account, not just this site", which is wrong, and shows the account-level role as the current one.

to narrow someone's access instead, remove them from the sites they should not reach.

## transferring ownership

`POST /api/sites/{siteId}/transfer-ownership` hands the site to another account in one step, or [`owlette site transfer-ownership`](/docs/cli/reference/site#transfer-ownership) from a terminal. only the current owner can do it. the new owner does not have to be on the site already; the outgoing owner stays on as an admin, and can then be removed like anyone else. there is no dashboard control for it.
