## first login

### email/password

1. Navigate to your dashboard URL (e.g., `https://owlette.app` or `https://dev.owlette.app`)
2. Click **Register** and create an account
3. After registration, you're automatically logged in

### google oauth

1. Click **"Sign in with Google"** on the login page
2. Select your Google account
3. You're automatically registered and logged in

### passkey (passwordless)

If you've registered a passkey, click **"Sign in with passkey"** on the login page. Authenticate the way you already unlock the device - Windows Hello, Touch ID, Face ID, a hardware security key, or a password manager that holds passkeys (1Password, Bitwarden, iCloud Keychain). No password, and no 2FA code either: the passkey satisfies both in the same step.

## set up two-factor authentication

After your first login you're taken to 2FA setup. It's required, but you choose how to satisfy it - a passkey or an authenticator app, and either one on its own is enough.

### passkey (recommended)

Choose **passkey** and approve the prompt with whatever already unlocks the device: Windows Hello, Touch ID, Face ID, a hardware security key, or a password manager that stores passkeys (1Password, Bitwarden, iCloud Keychain). These are all the same WebAuthn standard - there's nothing extra to install, and nothing to configure per vendor.

A passkey covers both halves of sign-in at once. Signing in with it proves who you are *and* clears the second factor in a single ceremony, so you're never asked for a code on top of it.

### authenticator app

Choose **authenticator app** if you'd rather use 6-digit codes:

1. Open an authenticator app (1Password, Bitwarden, Authy, Google Authenticator)
2. Scan the QR code displayed on screen
3. Enter the 6-digit code from your authenticator

Authenticator apps are **not phone-only**. 1Password, Bitwarden, and Authy all have desktop apps, so you can enroll and sign in without a phone in the loop at all.

### backup codes

Either route finishes on your **backup codes** - save them somewhere safe. They work for any factor, including a passkey-only account, and they're what gets you back in if you lose the device.

You can regenerate them later from account settings, but you'll have to prove a factor in the same step - a current 6-digit code, an unused backup code, or your passkey. A sheet of recovery codes is powerful enough to turn 2FA off outright, so a signed-in browser alone isn't enough to mint a new one.

<Callout type="idea" title={"you can change your mind later"}>

Add the other method (or more passkeys) any time from account settings. Removing your last factor is allowed - the account simply re-arms 2FA setup, and you'll be asked to enroll a new factor before you can use the dashboard again.

</Callout>

## create your first site

Sites are the top-level organizational unit - think of them as locations, departments, or projects.

1. If you have no sites yet, click **"create your first site"**. Otherwise open the site switcher, choose **"manage sites"**, then click **"new site"**.
2. In **"create new site"**, enter a **"site name"** (e.g., "NYC Gallery").
3. Keep the generated **"site ID"** or open **"customize site ID"** to set one manually. The ID is permanent and used in URLs.
4. Click **"create site"**.

You're automatically assigned as the owner with full access.

## add your first machine

1. Click **"add machine"** on the dashboard.
2. On the **"enter code"** tab, download or copy the agent installer link and run it on the target machine. The button detects the platform you are browsing from — Windows, macOS on Apple silicon, or Linux — and offers the other two in a menu.
3. Enter the 3-word **"pairing phrase"** shown on that machine.
4. Click **"authorize"**. The success state reads **"machine authorized"**, and the machine appears on the dashboard shortly.

For unattended or bulk installs, use the **"generate code"** tab instead. Click **"generate code"**, then copy the generated **"pairing phrase"** or **"silent install command"**. The silent install is Windows only; on macOS and Linux, pair from the app after installing. Generated pairing phrases expire in 10 minutes.

Within 30 seconds, the machine appears in your dashboard:

- Green **Online** indicator
- CPU, memory, disk metrics populating
- Agent version displayed

## understanding the dashboard layout

### machine cards

Each machine is displayed as a card showing:

- **Machine name** (hostname)
- **Online/Offline status** with last seen time
- **System metrics** - CPU, memory, disk, GPU percentages
- **Process list** - configured processes with status indicators
- **Agent version**

### view modes

- **Card View** - Visual grid of machine cards with sparkline charts
- **List View** - Compact table with sortable columns

### navigation

- **dashboard** - Main monitoring view
- **hoot** - AI chat for machine management
- **deploy** - Software deployment management
- **roost** - Content-addressed file sync, version publishing, and rollback at `/roosts`
- **logs** - Activity event viewer
- **admin panel** - Site admins manage members, agent tokens, schedule presets, alert rules, and webhooks for the sites they belong to
