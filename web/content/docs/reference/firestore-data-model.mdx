each section below lists a path, its fields, and its **access**: what `firestore.rules` lets a signed-in browser or a paired agent do directly. *server only* means the rules deny the path, or it falls through to the deny-all rule at the bottom, and only route handlers, Cloud Functions and workers reach it through the Admin SDK. the Admin SDK bypasses the rules, so every server write enforces its own checks.

"site members" means anyone with an active row in `sites/{siteId}/members` (`canAccessSite`), "site admins" a row whose role is `owner` or `admin` (`isSiteAdmin`), and "the agent" a paired agent acting on its own site and machine.

## sites

### `sites/{siteId}`

the site. **access**: site members read; writes are server only.

| field | type | notes |
| --- | --- | --- |
| `name` | string | site display name. |
| `owner` | string | uid of the site's owner: the creator, moved by an ownership transfer. no rule consults it — access comes from `members` — but it names the site's payer, whose plan applies to the site once [plans](/docs/plans) are enforced. |
| `createdAt` | timestamp | creation time. |
| `timezone` | string | IANA timezone for site-scoped scheduling. |
| `timeFormat` | string | `12h` or `24h`, the site's clock format. |
| `schedulesFollowSiteTime` | boolean | whether process launch windows use `timezone` instead of each machine's own clock. three-state: missing means the site was never asked, `false` that it declined; both behave as machine-local. see [timezones](/docs/dashboard/timezones#process-schedules). |
| `tier` | string | `core` or `pro`. read by `GET /api/sites/{siteId}`; nothing in the repo writes it. |
| `plan`, `tierUpgradedAt` | string, timestamp | billing metadata, read alongside `tier`. |
| `roostEnabled` | boolean | site-level roost kill switch. missing or `true` means enabled. |

`site_ids/{siteId}` is a tombstone (`{ deletedAt }`) written when a site is deleted, so its ID is never reused; any signed-in user can get one, and listing is denied. `deleted_sites/{siteId}` (server only) tracks the storage still to reclaim: `siteId`, `deletedAt`, `r2PrefixesToReclaim`, `reclaimed`.

### `sites/{siteId}/members/{uid}`

the row that grants site access. `canAccessSite()` and `isSiteAdmin()` resolve entirely from it; `sites/{siteId}.owner` and `users/{uid}.sites` are read by no rule.

**access**: a user may read only their own rows (`collectionGroup('members').where('uid','==',me)`, through a recursive `{path=**}/members/{memberUid}` rule); the full roster is served by the API under `SITE_MEMBER_MANAGE`. all writes are server only, through `web/lib/membership.server.ts`.

| field | type | notes |
| --- | --- | --- |
| `uid` | string | duplicated as a field, not only as the document ID, so the collection-group query can prove the rule. |
| `role` | string | `owner`, `admin` or `member`. `owner` is written only at site creation and by ownership transfer. |
| `status` | string | `active`. |
| `addedAt` | timestamp | |
| `addedBy` | string | uid of whoever granted access. |

### `sites/{siteId}/settings/{settingId}`

per-site settings. **access**: site members read; writes are server only.

| doc ID | written by | fields |
| --- | --- | --- |
| `cortex` | `PATCH /api/sites/{siteId}/hoot-settings` | `requireTier3Approval` (absent means `true`), `updatedAt`. autonomous hoot also reads `autonomousEnabled`, `directive`, `maxTier` (default 2), `cooldownMinutes` (default 15) and `escalationEmail` (true unless `false`), which no route writes — they are set in Firestore directly. see [autonomous mode](/docs/dashboard/hoot#autonomous-mode). |
| `swoop` | `PATCH /api/sites/{siteId}/swoop-settings` | `enabled` (only a literal `true` turns swoop on), `excludedMachineIds` (default `[]`), `membersMayWatch` (default `true`), `indicator` (`banner`, `tray` or `none`; default `banner`), `updatedAt`. agents never read it. |
| `display` | `PATCH /api/sites/{siteId}/display-settings` | `keepAwake` (missing means `true`: on by default), `updatedAt`. agents cannot read it; they learn it from `GET /api/agent/site`, and online machines get a `site_settings_refresh` command when it changes. |
| `alerts` | `PUT /api/sites/{siteId}/alerts` | `rules[]`: `{ id, name, metric, operator, value, severity (info, warning, critical), channels (email, webhook), enabled, cooldownMinutes }`. read by the metrics function to evaluate thresholds. |

`sites/{siteId}/settings/llm` is **dead**: the site-level LLM key was removed in 3.0.0 and nothing reads it. LLM keys live per user at `users/{uid}/settings/llm`.

### `sites/{siteId}/logs/{logId}`

the site's activity log, the one the dashboard shows. **access**: site members and the site's agents read; the server and the site's agents create (an agent only for its own `machineId`, and `timestamp`, `action`, `level` and `machineId` are required); only the server deletes.

| field | type | notes |
| --- | --- | --- |
| `timestamp` | timestamp | event time. |
| `action` | string | event type, such as `process_crash` or `command_executed`. |
| `level` | string | `info`, `warning` or `error`. |
| `machineId`, `machineName` | string | source machine. |
| `processName`, `processId` | string | optional process. |
| `details` | map or string | optional details. |
| `userId` | string | optional initiating user. |
| `screenshotUrl` | string | optional screenshot pointer. |
| `eventType` | string | optional agent alert type. |
| `exePath`, `suggestedPaths` | string, array | on `exe_missing` entries, when the agent found the missing path's context. |

### `sites/{siteId}/audit_log/{entryId}`

security-boundary audit records. **access**: site admins read; client writes are denied.

| field | type | notes |
| --- | --- | --- |
| `correlationId` | string | ties the record to the request. |
| `actor` | map | who acted: a user (with API key ID when through a key) or a system actor. |
| `capability` | string | the capability checked. |
| `target` | map | `{ kind, id, ... }`. |
| `outcome` | string | `allow`, `deny` or `error`. |
| `timestamp` | timestamp | |
| `metadata` | map | optional. swoop records name their event here, in `metadata.event`: `session_started`, `session_ended`, `session_denied`, `lease_denied`, `step_up_failed`, and host events. |
| `denyReason`, `errorCode`, `enforcementBypassed` | string, string, boolean | optional. |

hash-chained records from the `recordAuditEvent` function land in the same collection under their hash, with `sites/{siteId}/audit_log_meta/head` (`{ hash, recordedAt }`, server only) as the chain head.

### `sites/{siteId}/webhooks/{webhookId}`

webhook subscriptions. **access**: site admins read; plain members are denied, because an old document may still carry an in-document signing secret. all writes go through the API.

| field | type | notes |
| --- | --- | --- |
| `schemaVersion` | number | `1`. |
| `url`, `hostname` | string | delivery endpoint and its host. |
| `events` | string[] | subscribed events. |
| `description` | string | optional. |
| `paused` | boolean | delivery paused. |
| `createdAt`, `updatedAt`, `createdBy` | timestamp, timestamp, string | |
| `secretRotatedAt`, `previousSecretValidUntil` | timestamp, number (ms) | set by `rotate-secret`; the old secret keeps signing until the second. |
| `lastDeliveryAt`, `lastDeliveryStatus`, `failureCount` | timestamp, string, number | delivery health. |
| `disabled`, `disabledReason`, `disabledAt` | boolean, string, timestamp | set when the dispatcher disables a failing subscription. |
| `deletedAt` | timestamp or null | soft delete. |

subscriptions written by the older alert sender carry `name`, `enabled`, `lastTriggered`, `lastStatus` and `failCount` instead, and that sender sets `enabled: false` after 10 consecutive failures.

the signing secret lives apart, in `sites/{siteId}/webhook_secrets/{webhookId}` (`{ signingSecret, previousSigningSecret }`), which the rules deny to everyone. an in-document `secret` or `signingSecret` is read only as a fallback for old subscriptions.

deliveries are queued in the top-level `webhook_deliveries/{deliveryId}__{subscriptionId}` (server only) and sent by a function every minute: `id`, `subscriptionId`, `siteId`, `url`, `event`, `canonicalBody`, `headers`, `secret`, `attempt`, `state` (`pending`, `succeeded`, `failed`), `lastError`, `lastStatus`, `nextAttemptAt` and `createdAt` (ms), `completedAt`, `updatedAt`. see [webhooks](/docs/api/webhooks).

## machines

### `sites/{siteId}/machines/{machineId}`

presence, status, metrics, process state, reboot state and capability flags all live on the machine document; there are no `presence` or `status` child documents. the document ID is the machine ID: its hostname when first paired, kept from then on.

**access**: site members read; the agent reads and writes its own machine; control-plane writes from the web go through API routes.

| field | type | notes |
| --- | --- | --- |
| `machineId` | string | the machine ID. |
| `siteId` | string | owning site. |
| `online` | boolean | agent-reported online flag. the dashboard also checks heartbeat age. |
| `lastHeartbeat` | timestamp | updated with each heartbeat. |
| `pairedAt` | timestamp | written by the server when the machine first receives credentials, and kept on a re-pair. after a plan lapses, the machine with the earliest one stays live in the dashboard. missing on machines paired before it existed. |
| `agent_version` | string | agent build version. |
| `osFamily` | string | `windows`, `macos` or `linux`, written on every heartbeat. an unrecognized platform is reported verbatim; the dashboard treats that, and an absent field (agents before 4.0.0), as `windows`. |
| `arch` | string | `x64` or `arm64` (an unrecognized value verbatim). with `osFamily`, it picks the installer a fleet update sends. |
| `osVersion` | string | the OS as people name it — `Windows 11 Pro 24H2`, `macOS 15.6`, `Ubuntu 24.04.5 LTS` — shown under the hostname. computed once per agent process. |
| `machine_timezone` | string | legacy Windows timezone label. |
| `machine_timezone_iana` | string | IANA timezone. |
| `health` | map | `{ status, error_code, error_message, last_checked_at, last_error_at }`, written by the agent when its health changes. the health-check cron adds `staleSince` and `lastCronAlertAt`. |
| `capabilities` | map | numbers, `0` or `1`, written on every heartbeat as dotted paths: `swoop` (the streamer is installed and this machine can stream — every Windows machine, a Mac whose app reported Screen Recording granted, never Linux), `displayRemoteApply` (reported as `1` on every platform, though display apply works on Windows only), `keepAwake` (the agent follows the site's keep screens awake switch). the dashboard gates on `=== 1`. |
| `displayAwake` | map | `{ wanted, held, session, how, reason }`: what keep screens awake holds, written by the agent on each change. `wanted` is the site's `settings/display.keepAwake` as the agent last read it, `held` the service's own hold (system sleep, and on macOS the display), `session` the owlette app's (idle lock and screensaver, and on Windows the display; `null` without a fresh report from it), `how` the mechanism, and `reason` why a wanted hold is not fully held (`no_display` when nobody is signed in). missing on agents without `capabilities.keepAwake`. |
| `cortexEnabled` | boolean | per-machine hoot kill switch. missing means enabled. |
| `cortexStatus` | map | `{ online, lastHeartbeat, status, error }`, written only by the agent's local hoot process. `status` is `idle`, `thinking`, `tool_call`, `error` or `offline`. |
| `rebooting`, `shuttingDown` | boolean | power-operation flags. |
| `rebootScheduledAt`, `shutdownScheduledAt` | number | unix seconds: when the OS will actually restart or power off. the dashboard's countdown runs to it. |
| `rebootSource`, `rebootCancellable`, `rebootEntryId` | string, boolean, string | written with the flags: `scheduled` or `manual`, whether a cancel can still land, and the schedule entry that fired. the health-check cron clears `rebootCancellable`. |
| `rebootPending` | map | `{ active, processName, reason, timestamp }`: relaunch attempts ran out. see [restart pending](/docs/dashboard/machine-monitoring#restart-pending). |
| `rebootState` | map | last fired schedule entry plus the current reboot attempt. |
| `lastScreenshot` | map or null | `{ url, timestamp, sizeKB }`, the latest screenshot. |
| `liveView` | map | `{ active, interval, startedAt, expiresAt }`, unix seconds, while live view runs. |
| `swoopViewers` | number | viewers across live swoop sessions with an unexpired lease, recomputed by the server when sessions change (not on every lease renewal, so it can lag). missing until the first session. |
| `configChangeFlag` | boolean | set by the server after process-config writes. nothing in the agent reads it. |
| `metrics` | map | the current metrics payload, below. |

metrics use schema version 2, nested on the machine document:

| field | type | notes |
| --- | --- | --- |
| `metrics.schemaVersion` | number | `2`. |
| `metrics.profileHash` | string or null | matches `hardware/profile.signatureHash`. |
| `metrics.timestamp` | timestamp | write time. |
| `metrics.cpus` | map | CPU metrics keyed by profile ID. temperature is Windows only. |
| `metrics.memory` | map | memory percent and used GB. |
| `metrics.disks` | map | disk usage keyed by profile ID. |
| `metrics.diskio` | map | per-volume read/write throughput. empty off Windows. |
| `metrics.gpus` | map | GPU metrics keyed by profile ID: NVIDIA on Windows and Linux, the Apple GPU on a Mac. |
| `metrics.nics` | map | network interface throughput keyed by profile ID. |
| `metrics.network` | map | gateway, ping latency, packet loss and network health. |
| `metrics.primary` | map | the current primary CPU, disk, GPU and NIC IDs. |
| `metrics.processes` | map | runtime process status from the agent. |
| `metrics.displayDriftCount` | number | monitors that drift from the assigned layout. |

current agents delete the legacy singular `metrics.cpu`, `metrics.disk` and `metrics.gpu` after writing v2 metrics.

### `.../commands/pending` and `.../commands/completed`

the command queue: two singleton documents under `sites/{siteId}/machines/{machineId}/commands/`, each holding command IDs as top-level map fields. **access**: site members read; the server and the agent write. the full command list is in [agent commands](/docs/reference/agent-commands).

```json
{
  "restart_DESKTOP01_1712000000000": {
    "type": "restart_process",
    "status": "pending",
    "timestamp": "<server timestamp>",
    "auditCorrelationId": "optional",
    "process_name": "TouchDesigner"
  }
}
```

the server writes pending commands with `writeCommandFanOut()`. the agent listens to `commands/pending`, writes a `running` marker, runs the command, writes the result to `commands/completed` under the same ID, and deletes the field from `commands/pending`.

| field (completed) | type | notes |
| --- | --- | --- |
| `status` | string | `completed`, `failed`, `cancelled`, or an intermediate status such as `running`, `closing_processes`, `downloading`, `installing` or `uninstalling`. |
| `result` | any | the handler's result. usually a string; a JSON string for `mcp_tool_call`; an object for `capture_screenshot`. |
| `error` | string | on failure. |
| `completedAt`, `updatedAt` | timestamp | |
| `startedAt` | timestamp | on the `running` marker. |
| `deployment_id` | string | optional deployment correlation. |
| `type` | string | the command type, when the handler supplies it. |

### `.../hardware/{docId}`

**access**: site members read; the agent writes its own.

| doc ID | notes |
| --- | --- |
| `profile` | static CPU, disk, GPU and NIC inventory: `schemaVersion`, `signatureHash` (joins with `metrics.profileHash`), `capturedAt`, `agentVersion`, and the `cpus`, `disks`, `gpus`, `nics` arrays. |
| `display` | live display topology, assignment and drift. Windows agents only. |
| `displayModes` | on-demand display mode catalogue. Windows agents only. |

### `.../screenshots/{screenshotId}`

screenshot history, written by the server after an upload. **access**: site members read.

| field | type | notes |
| --- | --- | --- |
| `url` | string | storage URL for the image. |
| `timestamp` | timestamp or number | capture time. |
| `sizeKB` | number | image size. at most 10 MB. |
| `monitor` | number | the monitor captured, on uploads through the current pipeline. |

the history keeps the newest 20.

### `.../installed_software/{softwareId}`

the software inventory, written by the agent. the agent deletes and rewrites the whole collection on each sync; the document ID is `{name}_{version}`. **access**: site members read; the agent writes its own.

| field | type | notes |
| --- | --- | --- |
| `name`, `version` | string | |
| `publisher` | string | empty on macOS, where a bundle carries none. |
| `install_location` | string | install directory; on macOS, the bundle path. |
| `uninstall_command` | string | the registry's uninstall command on Windows; the bundle path on macOS; `apt-get remove -y <name>` on Linux. |
| `installer_type` | string | the detected installer family on Windows; `app` on macOS; `dpkg` on Linux. |
| `registry_key` | string | Windows only. |
| `detected_at` | timestamp | inventory write time. |

the source is the registry on Windows, application bundles under `/Applications` and each user's Applications folder on macOS, and `dpkg` on Linux.

### `.../metrics_history/{bucketId}`

metric history for the charts, appended by a Cloud Function on every machine-document write. **access**: site members read; the agent and the server write.

buckets are **hourly**, keyed `YYYY-MM-DD-HH`. older daily buckets keyed `YYYY-MM-DD` are still read.

| field | type | notes |
| --- | --- | --- |
| `samples` | array | one sample per minute, with abbreviated keys: `t` (unix seconds), `c` (CPU), `m` (memory), `d` (disk), `g` (GPU), `ct` and `gt` (CPU and GPU temperature), `nl` and `np` (latency and packet loss), `n` (per-NIC `{ i, tx, rx, tu, ru }`), `ds` (per-disk `{ i, p }`), `gs` (per-GPU `{ i, u, t }`), `dios` (per-volume `{ i, rb, wb, bu, mb }`). optional keys are absent when the machine does not report them. |
| `meta.lastSampleTime` | number | unix seconds of the last sample. |
| `meta.updatedAt` | timestamp | |
| `meta.resolution` | string | `1min`. |

### `.../logs/{logId}`

per-machine log shipping, separate from the site activity log. written only when the machine's local config sets `logging.firebase_shipping.enabled`. **access**: site members read; the agent creates (append only); the server updates and deletes.

fields: `timestamp` (unix seconds), `level`, `message`, `logger`, `filename`, `line`, `server_timestamp`, `machine_id`, `site_id`.

### `.../cortex/active-chat`

the bridge to local hoot on the agent, used by the public conversations API. **access**: site members read; the server and the agent write.

the web writes `pendingMessage`, `chatId`, `machineName`, `messages[]` (`{ role, content }`), optional `images`, `status: "pending"`, `response` and `updatedAt`. the agent moves `status` through `processing`, `streaming`, `complete` or `error`, and fills `response` (`{ content, complete, parts }`).

### `.../swoop_sessions/{sid}`

one swoop session. `sid` is a 32-character hex ID. **access**: server only — the rules deny every role, and a rules test asserts it. no key, token or relay credential is ever stored here.

| field | type | notes |
| --- | --- | --- |
| `sid`, `siteId`, `machineId` | string | |
| `state` | string | `pending`, `live` or `ended`. |
| `createdBy` | string | `user:<uid>`. |
| `startedAt` | number | ms. |
| `createdAt`, `updatedAt` | timestamp | |
| `viewers` | array | `{ viewerId, uid, ctl, joinedAt, leaseExpiresAt }`; `ctl` is whether that viewer holds control. |
| `continuityHash`, `continuityUsedAt` | string, timestamp | reconnect continuity. |
| `endReason` | string | `closed`, `idle`, `killed`, `lease_expired`, `session_cap`, `signal_lost`, `host_exit`, `revoked` or `error`. |
| `viewerReason`, `endedAt` | string, timestamp | the page's own reason for ending, and when. |

a daily cron (`/api/cron/swoop-retention`) closes sessions whose leases have expired and deletes sessions older than 30 days.

`.../swoop_step_up_revocations/current` (server only) holds `{ revokedAt (ms), updatedAt }`, written by a kill: it closes every open second-factor window on the machine.

## machine config and presets

### `config/{siteId}/machines/{machineId}`

process configuration and other settings that sync between the dashboard and the machine's `config.json`. **access**: the agent reads and writes its own; site members read; the server writes dashboard changes.

| field | type | notes |
| --- | --- | --- |
| `version` | string | config schema version. |
| `processes` | array | process config: `id`, `name`, `exe_path`, `file_path`, `cwd`, `priority`, `visibility`, `time_delay`, `time_to_init`, `relaunch_attempts`, `launch_mode`, the derived `autolaunch`, `schedules`, and optional `schedulePresetId`. `priority` and `visibility` are applied on Windows only. |
| `rebootSchedule` | map | the scheduled reboot config, applied offline from the agent's cache. |
| `displays` | map | display assignment and auto-restore settings. |
| `watchdog` | map | the agent watchdog's thresholds and budget. |
| `cortex` | map | local hoot: `enabled`, `apiKeyEncrypted` (encrypted with the machine-bound key), `provider`, `maxTier`, `directive`, `autonomousEnabled`. |

the `firebase`, `environment` and `sentry` sections of `config.json` stay on the machine: they are never uploaded and never pulled.

### preset collections

**access**: site members read; writes are server only.

| path | purpose | fields |
| --- | --- | --- |
| `config/{siteId}/schedule_presets/{presetId}` | process schedule presets | `name`, `description`, `blocks`, `isBuiltIn`, `order`, `createdBy`, `createdAt` |
| `config/{siteId}/reboot_presets/{presetId}` | restart schedule presets | `name`, `description`, `entries`, `enabled`, `isBuiltIn`, `order`, `createdBy`, `createdAt` |
| `config/{siteId}/project_distribution_presets/{presetId}` | roost upload presets, read by `/roosts` and edited from the upload dialog | `name`, `description`, `project_url`, `extract_path`, `verify_files`, `order`, `isBuiltIn`, `createdBy`, `createdAt` |
| `config/{siteId}/talon_presets/{presetId}` | talon presets | `name`, `description`, `template` (`{ name, description, trigger, condition, outputs, cooldownMinutes }`), `isBuiltIn`, `order`, `createdBy`, `createdAt`, `updatedAt` |

## deployments and installers

### `sites/{siteId}/deployments/{deploymentId}`

software deployment records. **access**: site members read; the server creates, updates, cancels, retries and deletes them.

| field | type | notes |
| --- | --- | --- |
| `name` | string | display name. |
| `installer_name`, `installer_url` | string | installer source. |
| `sha256_checksum` | string | required: agents refuse an install without it. |
| `silent_flags` | string | optional installer flags. |
| `verify_path` | string or null | optional post-install check. |
| `close_processes` | array | processes to close before installing. |
| `parallel_install` | boolean | install alongside existing versions. |
| `suppress_projects` | boolean | optional. |
