**last updated**: 2026-10-05

this page tracks how the CLI and SDKs reach public package registries. it is release status, not an endpoint reference: the API itself is live at owlette.app whether or not these packages are published.

until a package is published, install it from a checkout of the repository (see the [CLI overview](/docs/cli/overview), [Node SDK](/docs/api/sdk-node) and [Python SDK](/docs/api/sdk-python)).

do not publish to a registry from a local shell unless a package owner has approved the release, the version and the registry account in use.

## release workflows

each package has a GitHub Actions workflow that builds, tests and publishes it with OIDC trusted publishing, so no registry token is stored in the repository. every run first passes the security gate, and a real publish refuses to run unless the tag matches the package version.

| package | workflow | release tag | dist-tag or target |
|---|---|---|---|
| `@owlette/cli` | `.github/workflows/cli-publish.yml` | `cli-vX.Y.Z` or `cli-vX.Y.Z-pre` | prerelease versions publish under the matching dist-tag (`rc` for `1.0.0-rc.0`); stable versions under `latest` |
| `@owlette/sdk` | `.github/workflows/node-sdk-publish.yml` | `node-sdk-vX.Y.Z` or `node-sdk-vX.Y.Z-pre` | same rule as the CLI |
| `owlette-sdk` | `.github/workflows/py-sdk-publish.yml` | `py-sdk-v<version>`, for example `py-sdk-v1.0.0rc0` | a tag push publishes to PyPI |

- npm publishes carry provenance attestations. npm only lets you attach a trusted publisher to a package that already exists, so the first publish of each npm package must be done once with a token or a local `npm publish`; every later release goes through the workflow.
- PyPI supports a pending trusted publisher, so the first Python release can go through the workflow. configure the publisher on PyPI (project `owlette-sdk`, workflow `py-sdk-publish.yml`, no environment) and push the tag promptly: a pending publisher does not reserve the name.
- a manual run defaults to a dry run. the Python workflow also offers `target=testpypi`, which needs a matching pending publisher on TestPyPI.

if a local bootstrap or emergency publish is approved, record the operator, registry account, package, version and reason in the release notes.

## dry-run checks

run these from the repository root before requesting a publish. they work in any shell.

```bash
cd cli
npm ci
npm run build
npm test
npm pack --dry-run
```

```bash
cd sdks/node
npm ci
npm run build
npm test
npm pack --dry-run
```

```bash
cd sdks/python
python -m pip install --upgrade pip build twine
python -m pip install -e ".[dev]"
python -m pytest
python -m build --sdist --wheel
python -m twine check dist/*
```

do not commit generated `dist/`, `.egg-info/` or package archives. they are release artifacts, not source.

## local bootstrap publish

only for the first publish of each npm package, with an approved owner and account:

```bash
cd cli
npm publish --tag rc --access public
```

```bash
cd sdks/node
npm publish --tag rc --access public
```

then attach the trusted publisher on npmjs.com and confirm the `rc` tag points at the intended version:

```bash
npm view @owlette/cli dist-tags
npm view @owlette/sdk dist-tags
```

## launch gate

the packages are externally released when:

- npm and PyPI package ownership, two-factor authentication and recovery access are verified
- the license file is present in the CLI, Node SDK and Python SDK artifacts (each package directory ships one)
- the dry-run checks above pass from a clean checkout
- `@owlette/cli` and `@owlette/sdk` are published under the npm `rc` dist-tag
- `owlette-sdk` is published to TestPyPI, then PyPI, as a pre-release
- the install checks below pass on a clean machine for npm and PyPI
- the Homebrew, Scoop and winget install commands work from their public channels, or have an approved launch waiver

## install verification

run these in a clean temporary directory or a disposable VM. the CLI and both SDKs need Node.js 20 or later and Python 3.10 or later.

```bash
npm install -g @owlette/cli@rc
owlette --version
owlette roost --help
```

```bash
npm install @owlette/sdk@rc
node -e "const { VERSION } = require('@owlette/sdk'); console.log(VERSION)"
```

on macOS or Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install --pre owlette-sdk==1.0.0rc0
.venv/bin/python -c "import roost; print(roost.__version__)"
```

on Windows (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install --upgrade pip
.\.venv\Scripts\python -m pip install --pre owlette-sdk==1.0.0rc0
.\.venv\Scripts\python -c "import roost; print(roost.__version__)"
```

package-manager channels, once they exist:

```bash
brew install owlette        # macOS, linux
scoop install owlette       # Windows
winget install Owlette.CLI  # Windows
```

as of 2026-10-05, `@owlette/cli`, `@owlette/sdk` and `owlette-sdk` are not on npm or PyPI, and no Homebrew, Scoop or winget manifest exists. the release workflows are in place; the launch gate above is open until the registry publishes and install checks pass, or a waiver is approved.
