**last updated**: 2026-10-05

the official TypeScript SDK for the [owlette public API](/docs/api/overview). it wraps the REST surface in a typed resource tree and adds auto-retry, an automatic `Idempotency-Key` on every mutation, a chunk-aware roost `push()`, HMAC webhook verification, version-ref passthrough, and push progress events. if you can use `fetch` directly you can use this — it just adds the tedious bits.

---

## installation

```bash
npm install @owlette/sdk@rc
# or: pnpm add @owlette/sdk@rc
# or: yarn add @owlette/sdk@rc
```

the package ships CommonJS `.js` output plus `.d.ts` declarations. no native modules, no wasm, no postinstall script. it needs Node.js 20 or newer (`engines.node: ">=20"`).

`@owlette/sdk` is not on the npm registry yet — the `rc` tag goes out with the [distribution gate](/docs/api/distribution). until then, build it from a checkout of the owlette monorepo and install the folder:

```bash
# in the monorepo root
npm install
npm run build:sdk

# in your project
npm install <path-to-checkout>/sdks/node
```

## hello world (&lt; 10 lines)

```ts
import { Owlette } from '@owlette/sdk';

const owlette = new Owlette({ token: process.env.OWLETTE_TOKEN! });
const identity = await owlette.account.whoami();
const siteId = identity.primarySiteId ?? 'kiosk-fleet-01';
const result = await owlette.roosts.push('./dist', 'rst_abc', {
  siteId,
  description: 'initial publish',  // optional ≤500 chars, surfaced in the version-history ui
});
console.log('published', `v${result.versionNumber}`, result.versionId, '—', result.stats.uploadedChunks, 'chunks uploaded');
```

that's the whole flow: walk `./dist`, split every file into 4 MiB SHA-256 chunks, dedup-check against R2, upload what's missing, publish a version, and return the new ID plus `versionNumber`.

## authentication

every request sends `Authorization: Bearer <token>`. use an `owk_live_*` API key — new keys are always minted `live`, and legacy `owk_test_*` keys still authenticate the same way. create one in the dashboard at **settings → api keys** (see [creating keys](/docs/api/authentication#creating-keys)). the SDK reads no environment variables and no files: `OWLETTE_TOKEN` in these examples is your own convention.

```ts
const owlette = new Owlette({
  token: process.env.OWLETTE_TOKEN!,   // required — an owk_live_* api key
  apiUrl: 'https://owlette.app',       // default
  roostVersion: '2026-04-22',          // default — sent as the Roost-Version header
  retry: { maxAttempts: 5 },           // optional — see errors and retries below
  fetch: customFetch,                  // optional — proxy / mtls / tracing wrapper
  environment: 'live',                 // optional — stored on the client, never sent
});
```

`onBillingWarning` is still accepted for compatibility but never fires: the API stopped sending the `X-Owlette-Billing-Warning` header when billing was removed.

**scope enforcement is server-side.** the SDK does not validate scopes locally — a call the key does not cover fails with `OwletteApiError.code === 'scope_insufficient'`. see [scopes](/docs/api/authentication#scopes) for the grammar; permissions are exact, so `write` does not imply `read`.

the SDK adds an `Idempotency-Key` header to every mutating request (POST / PATCH / PUT / DELETE) unless you pass one: a call-specific key such as `sdk-processes-create-<uuid>` on the process, machine-command, hoot, member, user, and installer resources, and `node-sdk-<uuid>` everywhere else. the key is generated once per call and reused across the SDK's own retries. replay caching is route-specific: it protects endpoints whose handlers implement it, such as version publish/patch, rollback/deploy, webhook mutations, hoot conversation create/rename/delete, installer upload/set-latest, installer-deployment actions, and site/machine/process/member/user administration. it does not make roost create/update/delete, key create/rotate/revoke, chunk calls, or a hoot send replay-safe. see [idempotency](/docs/api/idempotency) for the replay window.

### account

```ts
const identity = await owlette.account.whoami();
console.log(identity.email ?? identity.userId, identity.key?.keyPrefix, identity.primarySiteId);

const version = await owlette.account.version();
console.log(version.current, version.supported);
```

`account.apiKeys` wraps `/api/account/api-keys`, a superadmin-only platform surface that acts on the caller's own keys. a key minted by an API-key caller copies that key's scopes, so it cannot widen them; a key minted from a session gets every permission on every resource. either way it expires after 90 days.

```ts
// superadmin only
const created = await owlette.account.apiKeys.create({ name: 'preview publisher' });
console.log(created.key);              // owk_live_...  <-- shown exactly once
const keys = await owlette.account.apiKeys.list();
await owlette.account.apiKeys.revoke(created.keyId);
```

### roosts

```ts
// list roosts in a site (cursor-paged) — returns { roosts, nextPageToken }
const page = await owlette.roosts.list({ siteId: 'site-1', pageSize: 20 });
for (const r of page.roosts) console.log(r.roostId, r.name, r.currentVersionId);
if (page.nextPageToken) {
  const page2 = await owlette.roosts.list({
    siteId: 'site-1',
    cursor: page.nextPageToken,
  });
}

// fetch one — includes currentVersion / previousVersion summaries
const r = await owlette.roosts.get('rst_abc', { siteId: 'site-1' });

// create — returns { roostId, siteId, name, targets }
const created = await owlette.roosts.create({
  siteId: 'site-1',
  name: 'lobby touchdesigner',
  targets: ['machine-a7f3'],            // machine ids
  extractPath: 'C:\\Projects\\lobby',   // optional
  roostId: 'rst_lobby_td',              // optional — 8-64 chars; server generates rst_<hex> if omitted
});

// patch (rename, retarget) — returns { roostId, siteId, updated }
await owlette.roosts.patch('rst_lobby_td', { siteId: 'site-1', name: 'lobby (v2)' });

// soft-delete — returns { softDeleted, tombstoneExpiresAt };
// creating the same id again within 30 days restores it
await owlette.roosts.remove('rst_lobby_td', { siteId: 'site-1' });

// publish from a directory — the flagship call
const { versionId, versionNumber, stats } = await owlette.roosts.push('./dist', 'rst_abc', {
  siteId: 'site-1',
  description: 'fixed broken lobby video',   // optional ≤500 chars
  onProgress: (evt) => console.log(evt),
});

// rollback — `targetVersion` accepts string | number:
//   3 / "3" / "#3" / "v3"            → the third publish for this roost
//   a 64-char version id             → that exact version (legacy "vrs_<hex>" still resolves)
//   "current" / "previous" / "first" → aliases resolved server-side
// omit it entirely to revert one step (equivalent to "previous").
await owlette.roosts.rollback('rst_abc', {
  siteId: 'site-1',
  targetVersion: 3,
});

// trigger a deployment (targeted / scheduled / dry-run)
const deploy = await owlette.roosts.deploy('rst_abc', {
  siteId: 'site-1',
  versionId,                            // optional — defaults to the roost's current version
  machines: ['machine-a7f3'],           // subset of targets — omit for the full target list
  scheduleAt: '2026-04-25T03:00:00Z',   // optional — iso-8601 utc or Date
  dryRun: false,
});

// a `scheduleAt` more than 60s out comes back as stage "scheduled" plus a
// `scheduled` object; the server sweep fires it within 5 minutes of that
// instant, or writes it off as missed if it is more than 30 minutes late.
// see /docs/api/versions#scheduled-rollouts
if (deploy.stage === 'scheduled') console.log(deploy.scheduled?.at);
```

`rollback()` and `deploy()` also take `idempotencyKey` to replace the generated key. version refs are passed to the server as you wrote them; see [version IDs and refs](/docs/api/versions#version-ids-and-refs).

### versions

```ts
// list versions for a roost (cursor-paged, newest first) — returns { versions, nextPageToken }
const page = await owlette.versions.list('rst_abc', { siteId: 'site-1', pageSize: 20 });
for (const v of page.versions) console.log(`v${v.versionNumber}`, v.versionId, v.description, v.createdAt);

// fetch one — `versionRef` accepts the same forms as rollback's targetVersion.
// the sdk url-encodes it, so "#3" is safe here.
const v = await owlette.versions.get('rst_abc', 'current', { siteId: 'site-1' });

// edit the description only (everything else on a published version is immutable)
await owlette.versions.patch('rst_abc', v.versionId, {
  siteId: 'site-1',
  description: 'updated release notes',
});

// file listing (paths + per-file chunk lists, paged; pageSize up to 500)
const files = await owlette.versions.files('rst_abc', 3, {
  siteId: 'site-1',
  pageSize: 500,
});

// diff two versions — `against` is the baseline; both sides accept any versionRef form
const diff = await owlette.versions.diff('rst_abc', 'current', {
  siteId: 'site-1',
  against: 'previous',
});
```

`list()`, `files()`, and `deployments.list()` take `pageSize` / `pageToken`; `limit` / `cursor` still work as deprecated aliases.

### chunks — low-level data plane

most users never touch these; `roosts.push()` is the high-level wrapper. when you need raw control (network shares, custom uploaders, reuse across roosts) the methods are here. hashes are bare lowercase SHA-256 hex, up to 1000 per call.

```ts
// dedup-check — returns the hashes r2 is missing
const missing = await owlette.chunks.check('site-1', [
  'ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12',
  'cd34cd34cd34cd34cd34cd34cd34cd34cd34cd34cd34cd34cd34cd34cd34cd34',
]);

// mint signed r2 put urls (60 min ttl) — returns { urls, expiresAt }
const { urls } = await owlette.chunks.uploadUrls('site-1', missing);
for (const [hash, url] of Object.entries(urls)) {
  await fetch(url, { method: 'PUT', body: await chunkBytes(hash) });
}

// mint signed r2 get urls (15 min ttl) — same { urls, expiresAt } shape
const { urls: downloadUrls } = await owlette.chunks.downloadUrls('site-1', [
  'ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12',
]);

// mount an existing chunk from one roost into another (no re-upload)
await owlette.chunks.mount(
  'ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12',
  'site-1',
  'rst_source',
  'rst_target',
);

// which roosts reference this chunk? — one page; pass { limit, cursor } to page
const refs = await owlette.chunks.referrers(
  'ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12ab12',
  'site-1',
);
```

### hoot

```ts
const conversation = await owlette.chat.new({
  siteId: 'site-1',
  machineId: 'machine-a7f3',            // omit for a site-wide conversation
  title: 'diagnostics',
});

const page = await owlette.chat.list({ siteId: 'site-1', pageSize: 10 });

const stream = await owlette.chat.send(conversation.conversationId, 'summarize machine health', {
  onDelta: (text) => process.stdout.write(text),
});
const reply = await stream.complete;      // or: for await (const d of stream.deltas) ...

await owlette.chat.rename(conversation.conversationId, 'lobby diagnostics');
await owlette.chat.delete(conversation.conversationId);
```

the SDK calls the canonical `/api/hoot/conversations` routes. a send carries only `role` (always `user`) and `content`: leave `SendMessageOptions.machineId`, `machineName`, and `role` unset, because the server answers any other field with `400 forbidden_field` and `chat.send()` throws a plain `Error` (not `OwletteApiError`) for any non-2xx. API-key callers are capped to read-only hoot tools during streamed replies.

<Callout type="warning" title={"chat.send() reads the older frame format"}>

the 1.0.0-rc.1 stream parser understands only line-prefixed `0:"…"` / `3:"…"` frames. replies that run server-side — every API-key caller — arrive as AI SDK UI-message lines (`data: {"type":"text-delta",…}`), which it skips, so `deltas` yields nothing and `complete` resolves to an empty string. a `3:` error before the model starts is still raised. until the parser is updated, read the response yourself as shown in [stream format](/docs/api/hoot#stream-format), or use [`owlette chat send`](/docs/cli/reference/chat#send).

</Callout>

### keys

`owlette.keys` wraps `/api/keys`, which takes a signed-in session or a Firebase ID token as the bearer token — an API key cannot create, list, edit, rotate, or revoke keys. build a separate `Owlette` with that token for these calls.

```ts
const admin = new Owlette({ token: firebaseIdToken });

const created = await admin.keys.create({
  name: 'ci publisher',
  scopes: [
    { resource: 'site', id: 'site-1', permissions: ['write'] },
    { resource: 'roost', id: '*', permissions: ['read', 'write', 'deploy'] },
  ],
  ttlDays: 90,                         // 1-365, default 90
});
console.log(created.key);              // owk_live_...  <-- shown exactly once

const all = await admin.keys.list();

// widen or narrow an existing key without reissuing the secret.
// `scopes` is a full replacement, not a merge.
await admin.keys.update(created.keyId, {
  scopes: [{ resource: 'roost', id: '*', permissions: ['read', 'write', 'deploy', 'rollback'] }],
});

// rotate: a new secret now, the old one keeps working for 24h
const rotated = await admin.keys.rotate(created.keyId, 90);
await admin.keys.revoke(rotated.keyId);
```

`create()` still accepts `environment` because older builds send it; the server ignores it and mints a `live` key.

## push progress

`owlette.roosts.push()` reports progress through the `onProgress` callback. it fires `discover` once, `hash` before each file (plus a final one with an empty `file`), `check-missing` once, `upload` every 4 chunks and on the last one, and `publish` only when the publish is retried.

```ts
await owlette.roosts.push('./dist', 'rst_abc', {
  siteId: 'site-1',
  onProgress: (evt) => {
    switch (evt.phase) {
      case 'discover':      console.log(`found ${evt.fileCount} files (${evt.totalBytes} bytes)`); break;
      case 'hash':          console.log(`hashing ${evt.file} (${evt.filesDone}/${evt.filesTotal})`); break;
      case 'check-missing': console.log(`${evt.missing} of ${evt.total} chunks need upload`); break;
      case 'upload':        console.log(`${evt.uploaded}/${evt.total} chunks uploaded`); break;
      case 'publish':       console.log(`retrying publish (attempt ${evt.attempt})`); break;
    }
  },
});
```

the result also carries `events`, an `EventEmitter` that emits the same events under `'progress'` — but `push()` only returns it once everything has already been emitted, so use `onProgress` for live progress.

### push options reference

```ts
interface PushOptions {
  siteId: string;                      // required — the site the roost belongs to
  name?: string;                       // optional — overrides the roost's name on publish
  targets?: string[];                  // optional — machine ids to retarget to on publish
  extractPath?: string;                // optional — on-disk extract root for the agent
  description?: string;                // optional — plaintext ≤500 chars, stored on the version doc
  onProgress?: (evt: PushProgressEvent) => void;
  ignore?: readonly string[];          // extra file or directory names to skip (exact match)
}
```

the walk always skips `.git` and `node_modules`, skips zero-byte files, and follows symlinks only when they resolve inside the directory. a directory with no non-empty files throws before any request.

**push is last-writer-wins.** the publish does not send `expectedCurrentVersionId`, so a version someone else published while you were uploading simply becomes your `previousVersionId`. on a `412` the SDK retries the publish up to 5 times before surfacing `OwletteApiError`; chunk uploads never re-run — they're already addressed by hash. a push also always mints a new version, even when no file changed, because the version body records when and where it was built.

## webhook signature verification

roost signs every webhook with `Roost-Signature: t=<unix_seconds>,v1=<hmac_sha256_hex>` (see [signature format](/docs/api/webhooks#signature-format)). the SDK ships a verifier that enforces a 5-minute replay window and compares with `crypto.timingSafeEqual`. `verifySignature()` returns `{ ok, reason, timestamp }`; it does not parse or return the webhook event:

```ts
import { verifySignature, isSignatureValid } from '@owlette/sdk';

// in your raw-body webhook handler:
const rawBody = req.rawBody;            // keep the original bytes/string
const sig = req.headers['roost-signature'];
const result = verifySignature(
  sig,
  rawBody,                             // MUST be the raw bytes, not parsed json
  process.env.WEBHOOK_SECRET!,
);
if (!result.ok) {
  // 'missing_header' | 'missing_timestamp' | 'missing_v1' |
  // 'timestamp_out_of_tolerance' | 'bad_signature'
  console.log('rejected:', result.reason);
  return res.status(401).json({ error: result.reason });
}
// safe to parse and process after verification
const bodyText = typeof rawBody === 'string' ? rawBody : rawBody.toString('utf8');
const event = JSON.parse(bodyText);
handleEvent(event);

// boolean shortcut for quick paths
if (!isSignatureValid(sig, rawBody, process.env.WEBHOOK_SECRET!)) return res.status(401).end();
```

the `reason` type also lists `malformed_header`, but the parser never returns it: unparseable pairs are skipped and surface as `missing_timestamp` or `missing_v1`. the same three functions hang off the client as `owlette.events.*`.

**tolerance window** defaults to 300 seconds; override via `verifySignature(sig, body, secret, { toleranceSeconds: 600 })` (`Infinity` skips the check). more than 15 minutes is almost always a bug — either your clock is wrong or you're replaying.

## errors

every non-2xx response from a wrapped call throws `OwletteApiError` with structured fields pulled from the RFC 7807 problem+json body:

```ts
import { Owlette, OwletteApiError } from '@owlette/sdk';

try {
  await owlette.roosts.get('rst_missing', { siteId: 'site-1' });
} catch (err) {
  if (err instanceof OwletteApiError) {
    console.log(err.status);            // 404
    console.log(err.code);              // 'not_found' — stable, machine-readable
    console.log(err.requestId);         // for support tickets
    console.log(err.problem);           // full problem+json body
    console.log(err.problem.docsUrl);   // https://owlette.app/docs/api/errors#<code>
  }
  throw err;
}
```

plain `Error`s come only from `chat.send()`, `captureScreenshot()`, and the signed-url PUTs inside `push()` and `installer.upload()`.

the SDK retries `429`, `5xx`, and network errors — 5 attempts, exponential backoff from 250ms capped at 8s, ±25% jitter. on a `429` it waits the problem body's `retryAfter` seconds instead, capped at twice the max delay. `401`, `403`, `404`, `412`, `422`, and other 4xxs bubble immediately — retrying them will never succeed. override any of `maxAttempts`, `baseDelayMs`, `maxDelayMs`, `jitter`, or `shouldRetry(err)` with the `retry` option.

**common codes** you'll hit early (full list: [errors](/docs/api/errors)):

| code                       | status | when it fires                                                          |
|----------------------------|--------|------------------------------------------------------------------------|
| `scope_insufficient`       | 403    | API key doesn't carry the resource+permission for this call            |
| `token_expired`            | 401    | key hit its `expiresAt` — rotate or mint a new one                     |
| `idempotency_key_mismatch` | 422    | same key replayed with a different body                                |
| `version_stale`            | 412    | a raw publish's `expectedCurrentVersionId` no longer matches the head  |
| `version_not_found`        | 404    | `targetVersion` / `versionRef` didn't resolve against the roost        |
| `rate_limited`             | 429    | see `retryAfter` — the SDK already honors it                           |
| `unsupported_version`      | 400    | `roostVersion` isn't one the server accepts — update this package      |

## cancellation

the low-level `owlette.http.request()` accepts an `AbortSignal`:

```ts
const ctl = new AbortController();
setTimeout(() => ctl.abort(), 30_000);
await owlette.http.request('/api/sites', { signal: ctl.signal });
```

most list/get helpers do not accept `AbortSignal`, but `chat.send()`, `machines.captureScreenshot()`, and `owlette.http.request()` do. for `push()`, throwing inside the `onProgress` callback is the current cooperative-cancel mechanism.

## custom fetch (proxy / mtls / tracing)

pass your own `fetch` to the constructor. the SDK treats it as opaque — same signature, same return type — and uses it for every API call plus the R2 chunk uploads in `push()`, the hoot stream, and the screenshot download. used for corporate proxies, client-cert auth, distributed tracing hooks, or deterministic test mocks.

```ts
import { ProxyAgent } from 'undici';

const dispatcher = new ProxyAgent(process.env.HTTPS_PROXY!);
const owlette = new Owlette({
  token: process.env.OWLETTE_TOKEN!,
  // node's built-in fetch is undici, so it honors a `dispatcher` on the init
  fetch: (url, init) => fetch(url, { ...init, dispatcher } as RequestInit),
});
```
