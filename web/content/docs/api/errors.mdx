## envelope

```json
{
  "type": "https://owlette.app/problems/validation-failed",
  "title": "validation failed",
  "status": 400,
  "detail": "page_size must be a positive integer",
  "code": "validation_failed",
  "errors": {
    "query.page_size": ["must be a positive integer <= 100"]
  },
  "docsUrl": "https://owlette.app/docs/api/errors#validation_failed",
  "requestId": "5d7f7c5b-2ed6-4a56-9b2c-47dd7c84f957"
}
```

| field | meaning |
|---|---|
| `type` | a stable URI for the problem class, such as `https://owlette.app/problems/not-found` |
| `title` | a short category, the same on every occurrence |
| `status` | the HTTP status, matching the response |
| `detail` | what went wrong this time. safe to show; not stable enough to parse |
| `code` | the stable machine-readable code. branch on this |
| `docsUrl` | this page, anchored at the code — every code below has an anchor |
| `requestId` | a correlation ID, also sent as the `X-Request-Id` header. quote it when you report a problem |
| `errors` | for validation failures, a map of dotted field path to messages, e.g. `body.siteId` or `query.page_size` |
| `param` | sometimes, the one header or field at fault |
| `instance` | on some errors, the internal operation name. diagnostic only |
| `error` | on some routes, a copy of `detail` kept for older dashboard callers. ignore it |

some codes carry extra fields — `required` on `scope_insufficient`, `expiredAt` on `token_expired`, `entitlement` and `upgradeUrl` on `plan_required`, `retryAfter` on `rate_limited`, `sent` and `supported` on `unsupported_version`, `missingChunks` on a publish `precondition_failed`, `quota` on `over_quota`. ignore fields you do not recognise; new ones may appear.

### routes with a different body

a few routes do not use the full envelope yet:

- the machine config and process control routes — `hoot-enabled`, `launch-mode`, `reboot-pending`, `reboot-schedule`, process create, update, delete, `start`, `stop`, `restart`, `kill`, and `schedule` — answer `{ "type": "about:blank", "title", "status", "code", "detail" }` without `requestId` or `docsUrl`. `code` is still the field to branch on. a `plan_required` refusal on them is the full envelope.
- `POST /api/sites/{siteId}/agent-tokens/revoke` validation errors, `POST /api/cli/device-code/poll`, and upstream failures on `GET /api/platform/touchdesigner/builds` answer a bare `{ "error": "..." }`.
- a rejected `mfaProof` on a swoop session start answers `{ "error", "code" }`.

## general codes

these can come from almost any route.

| code | status | meaning | what to do |
|---|---:|---|---|
| `unauthorized` | 401 | missing, malformed, unknown, or revoked credential | send a valid credential |
| `token_expired` | 401 | the API key is past its `expiresAt` | rotate or create a key |
| `plan_required` | 402 | the site's plan does not include the feature. not enforced during the beta | have the site's owner upgrade it; `entitlement` names what is missing |
| `forbidden` | 403 | the caller lacks the role or capability, or their account is deactivated | use a different caller, or change access in the dashboard |
| `scope_insufficient` | 403 | the API key lacks the resource, ID, and permission needed | add the scope named in `required` |
| `api_key_not_permitted` | 403 | the operation refuses API keys whatever their scopes | use a dashboard session |
| `mfa_challenge_required` | 403 | a session that has not passed its second factor, or an ID token for an account that holds one | pass the second factor at sign-in, or use an API key |
| `mfa_setup_required` | 403 | the account has to set up a second factor before its dashboard session or Firebase ID token is answered | set one up at `/setup-2fa` |
| `not_found` | 404 | absent, or hidden from this caller. a machine outside the caller's machine scope says `machine not found or no access` | check the ID and the caller's access |
| `validation_failed` | 400 | body, query, path, or header validation failed | fix the request using `detail` and `errors` |
| `forbidden_field` | 400 | the body has a field this operation does not accept | remove it |
| `unsupported_version` | 400 | `Roost-Version` names a date the server does not support | send a date from `supported`, or omit the header |
| `idempotency_key_required` | 400 | the route requires `Idempotency-Key` and it is missing | retry with a generated key |
| `idempotency_key_invalid` | 400 | `Idempotency-Key` is longer than 255 characters | use a shorter key |
| `idempotency_key_mismatch` | 422 | the key was used on this route with a different body | resend the original body, or use a new key |
| `conflict` | 409 | the request conflicts with the resource's current state | read the current state and decide again |
| `precondition_failed` | 412 | a route-specific precondition failed | satisfy it and retry |
| `payload_too_large` | 413 | the request exceeds a size limit | split or shrink it |
| `rate_limited` | 429 | a rate-limit bucket is exhausted | wait for `Retry-After` |
| `service_unavailable` | 503 | a dependency is unavailable — for example roost is switched off, or the audit log could not be written | retry with backoff |
| `internal_error` | 500 | an unexpected server error | retry with backoff; quote `requestId` if it persists |

### unauthorized

the request carried no usable credential: missing, malformed, unknown, revoked, or a rotated key past its 24-hour grace window. send a valid API key, session, or Firebase ID token.

a dashboard session ends here too once the account's password is reset or changed (within a minute), or a second factor is added or removed, if the session started before that. sign in again. see [ending sessions](/docs/reference/authentication#ending-sessions).

### token_expired

the API key's `expiresAt` has passed; the body carries `expiredAt`. rotate the key or create a new one.

### plan_required

`402`: the plan of the site the request acts on does not include what the request needs. plans apply after the beta and are not enforced yet, so no route returns this today. `entitlement` names the missing feature, and `upgradeUrl` is the caller's plan page, relative to the dashboard, which lists the sites they own with a link to each one's billing:

```json
{
  "type": "https://owlette.app/problems/plan-required",
  "title": "plan required",
  "status": 402,
  "detail": "this site's plan doesn't include remote control. upgrade to continue.",
  "code": "plan_required",
  "entitlement": "owlette.control",
  "upgradeUrl": "/settings/plan",
  "docsUrl": "https://owlette.app/docs/api/errors#plan_required",
  "requestId": "5d7f7c5b-2ed6-4a56-9b2c-47dd7c84f957"
}
```

| `entitlement` | refused |
|---|---|
| `owlette.sites` | creating a site once the caller's free site is taken, without `onPlan: true` from a signed-in session (an API key's is ignored), or at all while a further site of theirs is unpaid; or transferring a site on owlette free to an owner whose free site is taken. a create refusal carries `siteCreation` with the site to upgrade, and a blocked one points `upgradeUrl` at that site's billing section; see [adding a site](/docs/plans#adding-a-site) |
| `owlette.control` | remote commands other than `update_owlette`, `cancel_reboot`, `dismiss_reboot_pending`, `stop_live_view`, `cancel_mcp_tool` and `mcp_tool_call`; process start, stop, restart and kill; alert rules |
| `owlette.deployments` | creating, retrying and uninstalling deployments |
| `owlette.swoop` | starting and renewing swoop sessions |
| `owlette.hoot` | hoot messages and hoot's tool calls (`mcp_tool_call`) |
| `owlette.roost` | creating and editing roosts, uploading chunks, publishing and editing versions, deploying, resyncing and rolling back |
| `owlette.talons` | creating, editing, testing and reassigning talons |
| `owlette.webhooks` | creating a webhook subscription |
| `owlette.api_keys` | every site request made with an API key, reads and deletes included |

the plan of the site the request acts on decides, whoever makes it. `owlette.sites` is the exception: owlette free is counted per account, so it goes by the sites the caller, or the new owner, already owns. creating or rotating a key and signing in the CLI are never refused by a plan; a key is checked on each request, against the site it acts on. reads, deletes and cancellations are never refused on a session. a machine past the limit is refused at pairing, not here; see [plans](/docs/plans#adding-a-machine-past-the-limit). do not retry unchanged.

### forbidden

the caller is authenticated, but lacks the site role or capability the operation needs, or their account has been deactivated. a site the caller cannot access at all answers `404`, not `403`.

a caller whose access to the site is [limited to some machines](/docs/reference/authentication#machine-scope) gets `403` on the site-wide routes, such as settings, members, deployments, roost and webhooks, whatever their role; the machines list and the site's logs answer with only their machines. a machine outside that scope answers `404 not_found` (`machine not found or no access`), exactly as a machine that does not exist does.

a missing swoop capability (watching, control or the swoop settings) answers [`capability_missing`](#capability_missing) instead.

### scope_insufficient

the API key is valid but has no scope entry matching the operation. `required` names what is missing:

```json
{
  "type": "https://owlette.app/problems/scope-insufficient",
  "title": "insufficient scope",
  "status": 403,
  "detail": "insufficient scope: requires write on machine:machine_123",
  "code": "scope_insufficient",
  "required": { "resource": "machine", "id": "machine_123", "permission": "write" },
  "docsUrl": "https://owlette.app/docs/api/errors#scope_insufficient",
  "requestId": "5d7f7c5b-2ed6-4a56-9b2c-47dd7c84f957"
}
```

[edit the key's scopes](/docs/api/authentication#editing-key-scopes) to add it.

### api_key_not_permitted

the operation never accepts an API key, whatever its scopes: every swoop session route, swoop settings, and display settings. use a dashboard session. see [what an API key cannot do](/docs/api/authentication#what-an-api-key-cannot-do).

### mfa_challenge_required

the account holds a second factor, and the credential hasn't passed it: a session whose sign-in is still at `/verify-2fa`, or a Firebase ID token, which never carries one. pass the factor at sign-in and retry, or call the API with a key. see [sessions and ID tokens](/docs/api/authentication#sessions-and-id-tokens).

### mfa_setup_required

`403`: the account has no second factor and has to set one up (`requiresMfaSetup`), so its dashboard session and its Firebase ID token are refused everywhere except the routes that set one up. set up a passkey or an authenticator app at `/setup-2fa`. the account's API keys are not affected. see [the factor inventory](/docs/reference/authentication#the-factor-inventory).

### not_found

the resource does not exist, or exists and is hidden from this caller so its existence does not leak — a site you cannot access, or another user's hoot conversation.

### validation_failed

the body, query, path, or headers failed validation. `detail` says what, and `errors` maps each failing field. most route-specific input checks report this code with a field-level `errors` map rather than a code of their own.

### forbidden_field

the body includes a field the operation does not accept, such as anything but `role` and `content` on a hoot send, or anything but `title` on a hoot rename.

### unsupported_version

the `Roost-Version` header names a date the server does not support. the body lists the date you `sent` and the `supported` ones; `GET /api/version` lists them too.

### idempotency_key_required

the route requires an `Idempotency-Key` header. retry the same request with a generated key. see [idempotency](/docs/api/idempotency).

### idempotency_key_invalid

the `Idempotency-Key` header is longer than 255 characters.

### idempotency_key_mismatch

the same key was used on this route, within 24 hours, with a different body. resend the original body, or use a new key for the changed request.

### conflict

the request conflicts with the resource's current state — for example rotating or editing a key that was already rotated or revoked. read the current state before retrying.

### precondition_failed

a route-specific precondition failed. on a roost publish it means some chunks the version lists are not stored for the site; `missingChunks` holds up to 20 of them.

### payload_too_large

the request is over a size limit.

### rate_limited

a rate-limit bucket is exhausted. wait for `Retry-After` (also in the body as `retryAfter`). see [rate limits](/docs/api/rate-limits).

### service_unavailable

something the request needs is unavailable: roost is switched off for the site, or the caller's user record or the audit log could not be read or written — a privileged action that cannot be audited is refused rather than run. retry with backoff.

### internal_error

an unexpected server error. retry with backoff, and quote `requestId` if it keeps happening.

### quota_exceeded

reserved for storage refusals (`402`). no public route returns it today; see [roost storage](/docs/api/rate-limits#roost-storage).

## roost codes

| code | status | meaning |
|---|---:|---|
| `version_not_found` | 404 | a well-formed version ref matched nothing in this roost |
| `version_ref_malformed` | 400 | a `{versionRef}`, `targetVersion`, or `against` value is not an accepted form |
| `version_content_immutable` | 400 | a version `PATCH` included a field other than `siteId` or `description` |
| `version_stale` | 412 | `expectedCurrentVersionId` did not match the current pointer when the publish committed |
| `rollback_no_op` | 400 | the rollback target is already the current version |
| `version_url_missing` | 409 | the rollback target has no stored body location |
| <span id="roost_name_required" />`roost_name_required` | 400 | creating a roost without a `name` |

### version_not_found

the ref is well-formed but resolves to no version in this roost's history. check the roost ID and the ref.

### version_ref_malformed

accepted refs are an alias (`current`, `previous`, `first`), a version number (`3`, `#3`, `v3`), or a version ID (64-character SHA-256 hex, or a legacy `vrs_` ID). anything else is refused.

### version_content_immutable

a published version's content never changes; only its `description` can be edited. publish a new version instead.

### version_stale

the publish sent `expectedCurrentVersionId`, and another publish moved the roost's pointer first. re-read the roost and publish again if it is still what you want.

### rollback_no_op

the rollback target is already current, so nothing would change. treat it as already applied.

### version_url_missing

the target version's stored body location is missing, so machines could not fetch it. publish the content again.

see [versions](/docs/api/versions#errors) and [chunks](/docs/api/chunks#errors) for the full roost error tables.

## billing codes

a site's billing is changed from the dashboard, in site settings → billing, by the site's owner. the requests behind it need a signed-in session: an API key gets `api_key_not_permitted`, and anyone but the owner `forbidden` or `not_owner`. [plans](/docs/plans#upgrading-a-site) apply after the beta; until then nothing is billed, an upgrade or a switch answers `billing_unavailable`, and only stopping a site that is still billed goes through.

| code | status | meaning |
|---|---:|---|
| <span id="email_unverified" />`email_unverified` | 403 | upgrading a site before the owner's email address is verified |
| <span id="already_billed" />`already_billed` | 409 | upgrading a site that is already billed; switch its plan instead |
| <span id="not_billed" />`not_billed` | 404 | switching the plan of a site that is not billed, or stopping its billing. when the site was billed and its billing has since ended (a subscription cancelled after failed payments), the detail says so and the site can be upgraded again |
| <span id="billed_by_previous_owner" />`billed_by_previous_owner` | 409 | upgrading a transferred site, or switching its plan, while it is still billed to its previous owner. it can be changed once that billing period has ended |
| <span id="link_required" />`link_required` | 409 | the owner's email already has a tridant account, which has to be [linked](/docs/plans#if-your-email-already-has-a-tridant-account) first |
| <span id="site_billed_elsewhere" />`site_billed_elsewhere` | 409 | the site is already billed under another tridant account |
| <span id="site_is_default" />`site_is_default` | 409 | the site belongs to another tridant account and cannot move to the owner's |
| <span id="founders_sold_out" />`founders_sold_out` | 409 | the founders places for the plan are taken; the request can be sent again at the list price |
| <span id="subscription_paused" />`subscription_paused` | 409 | the owner's subscription is paused; resume it before adding a site |

## retry rules

retry with backoff:

- `429 rate_limited`, after `Retry-After`
- `500`, `502`, `503`, and `504`
- network failures and client timeouts, when the original mutation carried an `Idempotency-Key`

do not retry unchanged:

- `401`, `402` and `403`
- `404`
- `400` and `422`
- `409` and `412`, until you have re-read the current state

for mutating retries, reuse the `Idempotency-Key` only when the method, path, query, and body are identical. see [idempotency](/docs/api/idempotency).

---

## request IDs

every problem response carries `requestId` in the body and the same value in `X-Request-Id`, except the routes listed under [routes with a different body](#routes-with-a-different-body). log the status, the `code`, and the request ID for every failure; each retry gets its own. a retry that replays a cached success carries `Idempotent-Replayed: true` instead of running again.
