## request parameters

| parameter | meaning |
|---|---|
| `page_size` | items to return. defaults and maximums vary by route — see the [table below](#paginated-routes) |
| `page_token` | the previous response's `next_page_token`. omit it on the first request |
| `limit` | alias for `page_size`, accepted on every paginated route |
| `cursor` | alias for `page_token`, accepted on every paginated route |

when both a canonical name and its alias are sent, the canonical name wins.

a `page_size` that is not a whole number between 1 and the route's maximum is refused with `400 validation_failed`. the hoot conversation list is the exception: it clamps an out-of-range value into range instead.

---

## response fields

```json
{
  "roosts": [],
  "next_page_token": "",
  "nextPageToken": ""
}
```

- the collection field is named for the resource — `roosts`, `versions`, `records`, `webhooks`, and so on. some routes also repeat it as `items`.
- `next_page_token` is an empty string when there are no more pages.
- most routes also send `nextPageToken`, a camelCase alias with the same value. read `next_page_token`; the alias exists for older clients.

## paginated routes

| route | collection field | default | max |
|---|---|---:|---:|
| `GET /api/roosts?siteId=` | `roosts` | 20 | 100 |
| `GET /api/roosts/{roostId}/versions` | `versions` | 20 | 100 |
| `GET /api/roosts/{roostId}/versions/{versionRef}/files` | `files` (also `items`) | 100 | 500 |
| `GET /api/roosts/{roostId}/deployments` | `rollouts` (also `items`) | 20 | 100 |
| `GET /api/chunks/{digest}/referrers` | `referrers` (also `items`) | 50 | 200 |
| `GET /api/sites/{siteId}/deployments` | `items` | 25 | 100 |
| `GET /api/sites/{siteId}/logs` | `logs` | 50 | 200 |
| `GET /api/sites/{siteId}/audit-log` | `records` | 50 | 200 |
| `GET /api/sites/{siteId}/talons/{talonId}/runs` | `runs` | 20 | 100 |
| `GET /api/webhooks?siteId=` | `webhooks` | 20 | 100 |
| `GET /api/webhooks/{webhookId}/deliveries` | `deliveries` | 20 | 100 |
| `GET /api/installer` | `versions` | 20 | 100 |
| `GET /api/users` | `users` | 20 | 100 |
| `GET /api/hoot/conversations` | `data.conversations` | 25 | 100 |

shape differences to know about:

- `GET /api/sites/{siteId}/deployments` returns only `next_page_token`, with no camelCase alias.
- `GET /api/roosts/{roostId}/versions` also returns `nextCursor`, which is `null` on the last page.
- `GET /api/hoot/conversations` nests everything under `data`: read `data.next_page_token`.
- `GET .../versions/{versionRef}/files` uses a numeric offset internally, so its tokens look like numbers. treat them as opaque anyway — store and send back what you received, and never compute one.

lists not in this table return everything in one response and take no paging parameters — for example `GET /api/sites`, `GET /api/sites/{siteId}/machines`, and `GET .../machines/{machineId}/processes` (which sends `data.nextPageToken: null`).

## traversal

```bash
PAGE_TOKEN=""
while true; do
  URL="$OWLETTE_API_URL/api/roosts?siteId=$SITE_ID&page_size=25"
  if [ -n "$PAGE_TOKEN" ]; then
    URL="$URL&page_token=$(printf %s "$PAGE_TOKEN" | jq -sRr @uri)"
  fi

  PAGE="$(curl -fsS "$URL" -H "Authorization: Bearer $OWLETTE_API_KEY")"
  echo "$PAGE" | jq '.roosts[]'

  PAGE_TOKEN="$(echo "$PAGE" | jq -r '.next_page_token // ""')"
  [ -z "$PAGE_TOKEN" ] && break
done
```

- send the cursor back exactly as you received it, URL-encoded.
- do not use cursors as stable IDs, and do not assume offset semantics.
- repeat the same filters on every page.
- stop when the next token is empty.

## validation errors

an invalid `page_size` uses the shared problem envelope:

```json
{
  "type": "https://owlette.app/problems/validation-failed",
  "title": "validation failed",
  "status": 400,
  "detail": "page_size must be a positive integer",
  "code": "validation_failed",
  "errors": {
    "query.page_size": ["must be a positive integer <= 100"]
  },
  "docsUrl": "https://owlette.app/docs/api/errors#validation_failed",
  "requestId": "5d7f7c5b-2ed6-4a56-9b2c-47dd7c84f957"
}
```

when you send `limit` instead, the message and the `errors` key name `limit`. see [errors](/docs/api/errors) for the full envelope.
