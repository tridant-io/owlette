**last updated**: 2026-10-05

the happy path takes about 10 minutes once you have a site with one online machine.

## what you need

- an owlette account on `https://owlette.app` or `https://dev.owlette.app`.
- at least one site with a paired, online machine — Windows, macOS, or Linux.
- a bash-compatible shell, `curl`, and `jq`. on Windows, Git Bash works for the commands below.
- `uuidgen` for idempotency keys. in Windows PowerShell, `[guid]::NewGuid().ToString()` does the same.

use `dev.owlette.app` for trying things out, and `owlette.app` only when you mean to act on a real fleet. keys are per environment: a key minted on one does not work on the other.

## 1. create a scoped key

open **settings → api keys** (`/settings/api-keys`), choose **create key**, and set:

| field | value |
| --- | --- |
| name | `quickstart` |
| expiration | 30 or 90 days |
| scopes | `site=<your-site-id>:read`, `machine=*:read`, `machine=*:write` |

`machine=*` keeps the first run simple, because you may not know the machine ID until you list inventory. afterwards, [edit the key](/docs/api/authentication#editing-key-scopes) down to `machine=<machine-id>:read` and `machine=<machine-id>:write`.

copy the raw key immediately — owlette shows it once.

scripted creation is available through `POST /api/keys`, but it needs a signed-in user session or Firebase ID token; an existing API key cannot create keys.

## 2. export your environment

```bash
export OWLETTE_API_URL="https://dev.owlette.app"
export OWLETTE_API_KEY="owk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

for production, point `OWLETTE_API_URL` at `https://owlette.app` and use a key minted there.

a small helper for the rest of the guide:

```bash
api() {
  method="$1"
  path="$2"
  shift 2
  curl -fsS -X "$method" "$OWLETTE_API_URL$path" \
    -H "Authorization: Bearer $OWLETTE_API_KEY" \
    -H "Content-Type: application/json" \
    "$@"
}
```

## 3. verify the key

```bash
api GET /api/whoami | jq '{
  userId,
  email,
  keyId: .key.keyId,
  keyPrefix: .key.keyPrefix,
  scopes: .key.scopes,
  primarySiteId
}'
api GET /api/version | jq
```

you should see the scopes you granted. a `401` means the key was not copied exactly, or has expired or been revoked. a `403` later in the guide means the key is missing the scope named in the error body.

## 4. select a site

```bash
api GET /api/sites | tee sites.json | jq -r '.sites[] | [.id, .name] | @tsv'
export OWLETTE_SITE_ID="$(jq -r '.sites[0].id' sites.json)"
echo "$OWLETTE_SITE_ID"
```

an API key lists only the owner's sites that its `site` scopes name (`site=*` covers them all). if `sites` is empty, the key has no `site` scope, or the account has no access to a site.

## 5. select an online machine

```bash
api GET "/api/sites/$OWLETTE_SITE_ID/machines" \
  | tee machines.json \
  | jq -r '.machines[] | [.id, .name, .osFamily, .online] | @tsv'

export OWLETTE_MACHINE_ID="$(
  jq -r '.machines[] | select(.online == true) | .id' machines.json | head -n 1
)"
echo "$OWLETTE_MACHINE_ID"
```

`osFamily` is `windows`, `macos`, or `linux` (`null` on agents older than 3.4). if no machine ID is printed, pair an agent or wait for one to come online — the command endpoint refuses to queue work for an offline machine.

## 6. queue a safe screenshot command

`capture_screenshot` is a good first command: it changes nothing on the machine, and it runs through the same async command path as every other machine operation.

```bash
export IDEMPOTENCY_KEY="$(uuidgen)"

api POST "/api/sites/$OWLETTE_SITE_ID/machines/$OWLETTE_MACHINE_ID/commands" \
  -H "Idempotency-Key: $IDEMPOTENCY_KEY" \
  -d '{
    "type": "capture_screenshot",
    "params": { "monitor": "primary" },
    "timeout_seconds": 60
  }' | tee command.json

export OWLETTE_COMMAND_ID="$(jq -r '.data.commandId' command.json)"
echo "$OWLETTE_COMMAND_ID"
```

the response is `202 Accepted`:

```json
{
  "ok": true,
  "data": {
    "commandId": "cmd_...",
    "status": "pending"
  }
}
```

sending the same `Idempotency-Key` with the same body replays this response instead of queueing a second screenshot. the same key with a different body is `422 idempotency_key_mismatch`.

## 7. poll the result

```bash
for i in $(seq 1 20); do
  api GET "/api/sites/$OWLETTE_SITE_ID/machines/$OWLETTE_MACHINE_ID/commands/$OWLETTE_COMMAND_ID" \
    | tee command-status.json

  STATUS="$(jq -r '.data.status' command-status.json)"
  if [ "$STATUS" = "completed" ] || [ "$STATUS" = "failed" ]; then
    break
  fi

  sleep 3
done

jq '.data' command-status.json
```

`status` moves from `pending` (waiting for the agent) through `in_progress` to `completed` or `failed`. a completed screenshot includes a signed URL, freshly minted on every poll and valid for an hour:

```json
{
  "commandId": "cmd_...",
  "status": "completed",
  "result": {
    "screenshot_url": "https://...",
    "expires_at": "2026-10-05T19:30:00Z"
  },
  "createdAt": "2026-10-05T18:29:51.000Z",
  "updatedAt": "2026-10-05T18:29:58.000Z"
}
```

## troubleshooting

| symptom | fix |
| --- | --- |
| `401 unauthorized` | re-copy the raw `owk_` key, check you are calling the environment it was minted on, and check it has not expired or been revoked |
| `403 scope_insufficient` | add the scope named in the error's `required`. this guide needs `site=<id>:read`, `machine=<id or *>:read`, and `machine=<id or *>:write` |
| `409 machine_offline` | choose an online machine from step 5, or wait for the agent to reconnect |
| `422 idempotency_key_mismatch` | generate a new idempotency key when you change the command body |
| `jq: command not found` | install `jq`, or read the JSON by hand |
