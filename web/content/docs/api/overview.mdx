the dashboard and the API work on the same resources. use the dashboard for exploration and one-off admin work; use the API when a workflow should be repeatable, audited, or wired into another system.

## base URLs

| environment | base URL |
|---|---|
| production | `https://owlette.app` |
| development | `https://dev.owlette.app` |
| local development | `http://localhost:3000` |

API paths are rooted at `/api`. the rendered endpoint reference is at [`/docs/api`](/docs/api), and the raw OpenAPI document (JSON) at `/api/openapi`.

## core resources

| resource | purpose |
|---|---|
| sites | the tenant boundary for machines, members, quotas, logs, webhooks, deployments, and roost content |
| machines | agents on Windows, macOS, and Linux machines registered to a site |
| commands | async work queued to a machine, such as screenshots, restarts, or process actions |
| processes | the monitored processes configured on each machine |
| deployments | installer fan-out records and per-target status |
| roosts | content-addressed project folders: versions, chunks, rollouts, and rollback |
| hoot | AI diagnostics over [`/api/hoot/conversations`](/docs/api/hoot) |
| webhooks | outbound event subscriptions and their delivery history |
| API keys | scoped credentials for automation |

## shared conventions

- **authentication** uses scoped `owk_live_*` API keys in `Authorization: Bearer ...` (or `x-api-key`); the dashboard and setup flows use sessions or Firebase ID tokens. see [authentication](/docs/api/authentication).
- **errors** use `application/problem+json` with a stable `code`, a `docsUrl`, and a `requestId`. see [errors](/docs/api/errors).
- **pagination** uses `page_size`, `page_token`, and `next_page_token`. see [pagination](/docs/api/pagination).
- **idempotency** uses `Idempotency-Key` for safe retries of the mutations that honor it. see [idempotency](/docs/api/idempotency).
- **rate limits** report `RateLimit-*`, `Retry-After`, and `Roost-Rate-Limited-Reason` headers where a limiter applies. see [rate limits](/docs/api/rate-limits).

## developer path

1. start with the [quickstart](/docs/api/quickstart): create a key, verify it, list inventory, queue a safe machine command, and poll it.
2. read the shared convention pages: [authentication](/docs/api/authentication), [pagination](/docs/api/pagination), [idempotency](/docs/api/idempotency), [errors](/docs/api/errors), and [rate limits](/docs/api/rate-limits).
3. use the [interactive reference](/docs/api) for each operation's scope, parameters, required headers, and response shape.
4. check [SDK and CLI distribution](/docs/api/distribution), then the [Node](/docs/api/sdk-node) and [Python](/docs/api/sdk-python) SDK pages when you want typed clients.
5. move on to the resource guide you need: [chunks](/docs/api/chunks), [versions](/docs/api/versions), [hoot](/docs/api/hoot), or [webhooks](/docs/api/webhooks).
