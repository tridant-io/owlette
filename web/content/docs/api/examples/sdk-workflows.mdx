title: "SDK workflow examples"
description: "small runnable SDK examples live in the Node and Python SDK example folders and run against a dev or staging tenant with explicit env vars."
---

- `sdks/node/examples/*.ts`
- `sdks/python/examples/*.py`

they are designed to run against a dev or staging tenant with explicit env vars.
they do not read local credential files.

for CI/CD examples, see [CI/CD with GitHub Actions](/docs/api/examples/ci-cd-github-actions).

## setup

neither SDK is on a registry yet (see [distribution](/docs/api/distribution)), so run the examples from a checkout of the owlette monorepo:

```bash
# node — the workspace links @owlette/sdk to sdks/node, which must be built first
npm install
npm run build:sdk

# python — the examples import the `roost` package
pip install -e sdks/python
```

`npx tsx` fetches `tsx` on first use. the Python `auto_rollback.py` example also needs `pip install aiohttp`.

## dev fixture env

use the same values for the Node and Python examples:

```bash
export OWLETTE_API_URL=https://dev.owlette.app
export OWLETTE_TOKEN=owk_live_...
export OWLETTE_SITE_ID=site_...
export OWLETTE_MACHINE_ID=machine_...
export OWLETTE_ROOST_ID=rst_...
export BUILD_DIR=./dist
export OWLETTE_WEBHOOK_SECRET=whsec_...
```

optional write gates:

```bash
export OWLETTE_DEPLOY=1
export OWLETTE_DISPATCH_COMMAND=1
```

leave those unset for read-only inspection and existing-command polling.

## auth and inventory

lists the caller identity, API version, visible sites, and machines for the
selected site.

```bash
npx tsx sdks/node/examples/auth-inventory.ts
python sdks/python/examples/auth_inventory.py
```

## roost push and deploy

publishes `BUILD_DIR` to `OWLETTE_ROOST_ID`. deployment is skipped unless
`OWLETTE_DEPLOY=1`.

```bash
npx tsx sdks/node/examples/run-roost-workflow.ts
python sdks/python/examples/run_roost_workflow.py
```

## command polling

poll an existing command:

```bash
export OWLETTE_COMMAND_ID=cmd_...
npx tsx sdks/node/examples/command-poll.ts
python sdks/python/examples/command_poll.py
```

dispatch and poll a new safe screenshot command:

```bash
export OWLETTE_DISPATCH_COMMAND=1
export OWLETTE_COMMAND_TYPE=capture_screenshot
npx tsx sdks/node/examples/command-poll.ts
python sdks/python/examples/command_poll.py
```

`OWLETTE_COMMAND_TYPE` defaults to `capture_screenshot` and also accepts `reboot_machine` or `shutdown_machine`. `OWLETTE_MONITOR` (default `primary`), `OWLETTE_POLL_SECONDS` (default `1.5`), and `OWLETTE_TIMEOUT_SECONDS` (default `60`) tune the poll.

## webhook verification

verify a real delivery by piping the raw body and signature:

```bash
cat body.json | OWLETTE_SIGNATURE='t=...,v1=...' npx tsx sdks/node/examples/webhook-verify.ts
cat body.json | OWLETTE_SIGNATURE='t=...,v1=...' python sdks/python/examples/webhook_verify.py
```

with no signature env var, both scripts sign the body with
`OWLETTE_WEBHOOK_SECRET` first and verify the generated fixture. that mode is
useful for CI syntax/import checks without a live webhook delivery. with no
body on stdin they sign a built-in sample body, and `OWLETTE_TOLERANCE_SECONDS`
overrides the 300-second replay window.

## recipe ports

the SDK folders also carry SDK versions of the raw REST recipes. they read their own env vars, listed at the top of each file:

| recipe | Node | Python | env |
|---|---|---|---|
| [nightly directory sync](/docs/api/examples/nightly-sync) | `nightly-sync.ts` | `nightly_sync.py` | `OWLETTE_TOKEN`, `ROOST_SITE_ID`, `ROOST_ID`, `WATCH_DIR`, optional `ALERT_WEBHOOK` |
| [bulk roost creation](/docs/api/examples/bulk-create) | `bulk-create.ts <csv>` | `bulk_create.py <csv>` | `OWLETTE_TOKEN` |
| [CI/CD publish](/docs/api/examples/ci-cd-github-actions) | `ci-cd.ts` | `ci_cd.py` | `OWLETTE_TOKEN`, `ROOST_SITE_ID`, `ROOST_ID`, optional `BUILD_DIR` (default `./build`) |
| [auto-rollback](/docs/api/examples/auto-rollback) | `auto-rollback.ts` | `auto_rollback.py` | `OWLETTE_TOKEN`, `WEBHOOK_SIGNING_SECRET`, `SLACK_WEBHOOK_URL`, `AUTO_ROLLBACK_SITE_IDS`, optional `PORT` |

each also honors `OWLETTE_API_URL` (default `https://owlette.app`). the SDK nightly-sync ports call `roosts.push()` unconditionally, and a push always mints a new version, so they publish every run; the raw REST recipe diffs first and only publishes on a real change.

## CI note

these examples are intentionally gated by env instead of running against a
shared live tenant by default. a CI job can validate the offline webhook fixture
without network access, and a dev/staging smoke job can run the full set by
providing the fixture env above.
