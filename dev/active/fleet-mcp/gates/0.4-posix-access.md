# Gate 0.4 — macOS and Linux access

**Linux: measured 2026-11-10 on the kiosk VM** (Ubuntu 24.04, agent 4.1.27 from the release package, GDM autologin user `kiosk`).
**macOS: measured 2026-11-11 on the MacBook** (TEC-MBA, macOS 26.6, agent 4.1.27 from the release package, console user `rosco`). The gate is met on both platforms.

## Linux

| question | answer | how it was measured |
|---|---|---|
| who runs the service | root | `ps`: `root … /opt/owlette/python/bin/python3 /opt/owlette/agent/src/owlette_runner.py` |
| is the console user in the service group | yes | `id`: `uid=1000(kiosk) … groups=…,1001(owlette)` |
| can the console user run the bundled interpreter and import the agent's modules | yes | as `kiosk`: `/opt/owlette/python/bin/python3` importing `shared_utils`, `auth_manager`, `firestore_rest_client` from `/opt/owlette/agent/src` |
| data root | `/var/lib/owlette`, `drwxr-x--- root owlette` | `ls -la` |
| `ipc/`, `tmp/`, `config/` | `drwxrwx--- root owlette` | `ls -la` |
| `logs/`, `cache/` | `drwxr-x--- root owlette` | `ls -la` |
| token store | `.tokens.enc`, `-rw------- root root`: the console user cannot read it | `ls -la`; `AuthManager.is_authenticated()` is false as `kiosk` |
| can the console user read a 0640 `root:owlette` file under `ipc/` | yes | `ipc/cortex_token.json`, written by the service in the local hoot fix, read by a process running as `kiosk` |
| can an account outside the group read it | no, by mode: the data root itself is 750 `root:owlette` | `ls -la` |

**What the session file needs on Linux**: `ipc/fleet/session.json`, mode 0640, owner root, group `owlette`, written through `shared_utils.open_new_file` and `shared_utils.grant_data_group` with an explicit `fchmod`, replaced atomically. `ipc/fleet` is created by `ensure_data_directories`; any directory under `ipc/` is 0770 by the mode table's default.

**Launch command on Linux**: `/opt/owlette/python/bin/python3 /opt/owlette/agent/src/fleet_mcp.py`, runnable by the console user as is.

## macOS

| question | answer | how it was measured |
|---|---|---|
| who runs the service | root | `ps`: `root … /Library/Application Support/Owlette/runtime/python/bin/python3 …/runtime/agent/src/owlette_runner.py` (LaunchDaemon `app.owlette.agent`) |
| is the console user in the service group | yes | `stat -f%Su /dev/console`: `rosco`; `id`: `groups=20(staff),501(_owlette),…` |
| can the console user run the bundled interpreter and import `mcp` | yes | as `rosco`: `…/runtime/python/bin/python3 -c "import mcp"`: Python 3.11.16, mcp 2.2.0 |
| data root | `/Library/Application Support/Owlette`, `drwxr-x--- root _owlette` | `ls -ld` |
| `ipc/`, `tmp/`, `config/` | `drwxrwx--- root _owlette` | `ls -ld` |
| `logs/` | `drwxr-x--- root _owlette` | `ls -ld` |
| `runtime/` and `runtime/agent/src` | `drwxr-xr-x root wheel`, inside the 750 data root: only the group gets that far | `ls -ld` |
| can the console user read a 0640 `root:_owlette` file under `ipc/fleet/` | yes | a test file made with sudo, read with `cat` as `rosco` |
| can an account outside the group read it | no | `sudo -u nobody cat`: `Permission denied` |

The test file and the `ipc/fleet` folder made for it were removed; nothing else was changed.

**What the session file needs on macOS**: the same as on Linux with the group `_owlette`: `ipc/fleet/session.json`, mode 0640, owner root, written through `shared_utils.open_new_file` and `shared_utils.grant_data_group`.

**Launch command on macOS**: `"/Library/Application Support/Owlette/runtime/python/bin/python3" "/Library/Application Support/Owlette/runtime/agent/src/fleet_mcp.py"`, runnable by the console user as is. Both paths hold a space.

Still true from the packaging scripts: the package's postinstall adds only the user at the console during the install to `_owlette` (`agent/packaging/macos/scripts/postinstall`). An account that signs in later is not in the group and cannot start the interpreter; the desktop app has the same limit.

## Shared findings

- A second account signing in on the same machine is not handled by the existing user-session files either (the pid file and the log are created by the first account), so the session file being group-readable is in line with what is there.
- Every member of the service group can read a 0640 group file, not only the console user. The value is a 15-minute fleet-only session, written only for a machine with a grant.
