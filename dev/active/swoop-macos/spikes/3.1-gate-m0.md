# Task 3.1: gate M0 — the app's child sees the screen

**Status**: not run. Prepared on 2026-09-29; waiting for the owner at the Mac. **No verdict yet.**

The question: when the installed app launches `owlette-swoop` as its own child, does macOS credit the app's
Screen Recording grant to that child for ScreenCaptureKit? Wave 4 depends on a yes.

## Before the install (2026-09-29, about 23:25 Mac time)

- The Mac runs the released 4.0.6: `/Applications/owlette.app` (installed 2026-09-28), signed with the hardened
  runtime by the team's Developer ID. `Contents/MacOS` holds `owlette-desktop` only: no streamer.
- The daemon (`system/app.owlette.agent`) and the app (`gui/<uid>/app.owlette.desktop`) are both running.
- `ipc/tcc.json` reads `{"screen_recording":true,"checked_at":…}`, about 100 s old when read.
- `ipc/swoop` and `logs/swoop` exist: `drwxrwx--- root:_owlette`. The console user is in `_owlette`.
- The installed runtime has no `swoop_spawn_posix.py` yet. It arrives with the new pkg.

## The pkg to install

- Built by the branch's signed build job from `b91adfae` (all of Wave 2): `BUILD-EXIT=0`, `status: Accepted`,
  stapled, and `stapler validate` passes.
- `~/src/owlette-swoop-mac/agent/build/macos/Owlette-Installer-v4.0.6.pkg`, 137,305,533 bytes.
- sha256 `8199d5f7f8d174d62f171619c334241578116446e272bd747b2555fdf7214ccb`.
- Same version as what is installed (4.0.6), so this is a reinstall of the same number with new contents.

## The script

`m0_selfcheck.py` (beside this memo; staged at `~/src/m0_selfcheck.py` on the Mac). It runs as root under the
runtime's interpreter with the runtime's `agent/src` on its path. It uses `swoop_spawn_posix`'s own `_listen`
and `_launch_job`, swaps the job's args for `["selfcheck", "--force"]`, submits it through `osadapter.run_job`,
accepts the connection, reads one line, and prints one json object: the launch result, the peer and console
uids, the streamer's line, and the exit file. It captures nothing.

```
sudo "/Library/Application Support/Owlette/runtime/python/bin/python3" ~/src/m0_selfcheck.py --label <run>
```

## What is already known, and what it does not show

- Task 2.1 ran `selfcheck` on the Mac from a plain ssh shell, from its own build tree:
  `{"screenCapturePreflight":true,"shareableContent":"ok","displays":1,"postEventPreflight":true,
  "axTrusted":true,"localNetworkSend":"ok","pid":24852}`.
- That process was a child of the ssh daemon, which holds its own Screen Recording and Accessibility grants
  (Task 1.2). It shows the verb works and that ScreenCaptureKit answers a process with no run loop. It says
  nothing about the app's child.

## Go / no-go

- **Go**: `shareableContent: ok` with `displays` at least 1, from the launch job.
- **No-go**: `denied`, an error, or a dialog that names `owlette-swoop` instead of owlette. Then the plan stops
  before Wave 4: the fallback is capture inside the app process, which is a re-plan.
