## 0. bad news first

1. **Every fielded swoop agent is refused its bundle today.** `web/app/api/agent/swoop/bundle/route.ts:128-133`
   compares the agent's `agentVersion` with `SWOOP_MIN_AGENT_VERSION` and returns 403 `agent_too_old` below it.
   The constant is `'3.4.0'` (`web/lib/versionUtils.ts:169`). The agent sends `shared_utils.APP_VERSION`
   (`agent/src/swoop_spawn.py:216`), which is `3.3.7` (`agent/VERSION`). So on dev, and on prod once swoop is
   enabled, a ring reaches TEC-A4D, the agent fetches the bundle, gets 403, and no streamer starts. The 2026-09-19
   live session only worked because `versionUtils.ts` was patched to 3.3.5 on the box (tasks.md:1879-1880). The
   Log (tasks.md:937-939) and `web/hooks/useFirestore.ts:272` call the constant "advisory copy". It is not. It is
   an enforced gate. The tests pass because they send the constant itself as `agentVersion`
   (`web/__tests__/api/swoop/agent-routes.test.ts:115`). This is the first thing to fix, and the owner has to pick
   the floor version (question 1).
2. **G2 and G3 are formally unmet.** No G2 memo exists in `spikes/` (tasks.md:603 requires one). No product
   session has run over a real LAN hop (tasks.md:1870-1873).
3. **The reinstall removed the LAN inbound firewall rules.** They were made by hand because
   `SwoopManager.set_enabled()` has no production caller (`agent/src/swoop_manager.py:145`, tasks.md:1876-1877).
   The rules are gone now, and no code will recreate them.
4. **The progress header is off by one.** It says 63/80 (tasks.md:2), but the file has 62 `[x]` and 18 `[ ]`.
   The "63" probably counts half of 7.7.
